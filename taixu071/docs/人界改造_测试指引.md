# 人界改造：本阶段测试指引

## 更新与启动

```bash
git pull origin master
npm ci
npm run typecheck
npm run test:foundation
npm run dev
```

在浏览器打开 Vite 输出的地址。建议 Chrome 或 Edge 开启硬件加速；这些测试不会删除已有存档，但开发版本仍建议先备份。自动化测试仅覆盖新增基础功能，不代表整个游戏已测试完成。

## 1. 画质与帧率

进入游戏打开设置：

1. 点击“集显优先 · 60”，确认画质为流畅优先、帧率上限为 60；点击“高画质 · 不限帧”，确认画质为高且上限为不主动限制；点击“自动 · 60”，确认切回自动并设置 60。
2. 分别修改帧率为 30、60、不主动限制，关闭设置后按 F3 查看帧率。不要在打开菜单时作为游戏性能基准；窗口切到后台可能被浏览器限速。独显/高刷新屏的不限帧仍可能被显示器或浏览器限制。
3. 在天南野外、城镇人多处和战斗中各观察 1–2 分钟，记录帧率、最慢帧、分辨率、画质、显卡型号、浏览器版本。集显 60 FPS 是目标，尚未经代表性硬件验证。
4. 重新进入游戏确认帧率选项记住。自定义树木密度、世界层分辨率等仍由独立设置控制；快捷方案目前只调整画质档与帧率。

## 2. 人物与服装

1. 打开衣橱（I 键或“衣”按钮），试男女角色的“行云道袍”“月影轻衣”，切换染色。
2. 在“自定义配色”修改衣袍、内衫、镶边等，确认预览变化；点“恢复当前染色”恢复。切换服装或预设染色时会清除自定义配色。
3. 在“容貌”调整眼部高度、眼裂宽度、鼻部高度、嘴部高度及面痣；在“身形”调整臂长。拖动人物转身，在近景查看细节。
4. “发饰”页切换耳饰与花钿，切换到“无”后应消失。预览受击、闪避等动作，观察错位、闪烁、穿模。
5. 关闭衣橱后查看人物；保存并重新读档，检查外观和颜色是否保留。以实际游戏存读档结果为准，本阶段没有完成全流程浏览器验证。

## 3. 地域名称

地图标题和跨地图名称使用天南、乱星海、大晋；三地属于同一人界。旧剧情/地点文案中仍有历史改名后的文字，尚未完成全面名称统一；跨地域旅行逻辑本阶段未重做。

## 反馈请包含

设备 CPU/GPU、系统、浏览器、屏幕分辨率与刷新率；发生地点、画质及帧率设置；复现步骤、实际和预期结果，有条件附 F3 截图或短视频。若发现存档或运行异常，先保留原始存档，不要反复覆盖。

## 当前边界

这不是完整人界重构。现有游戏仍使用外部视觉素材；新脸部和衣服使用现有人物程序绘制引擎，但程序化场景、全部装备、统一战斗数值及完整 WebGL 性能优化尚未完成。

## 本轮补充：服饰组合与存档保护

1. 打开衣橱，在衣裳下方的“款式搭配”分别选择衣领、袖型、衣长、下裳、外罩和纹样；预览站立、行走、施法和转身。部分组合本身可能存在遮挡或不协调，请记录具体服装和选项。
2. 修改配色后切换染色：款式选择应保留，配色回到新染色；点击“恢复当前衣裳款式”应只重置款式，不清除当前颜色。切换到其他衣裳会重置自定义款式与配色。
3. 自定义款式后存档、读档，确认款式和颜色仍在。正常情况下不应出现数值异常的存档提示。
4. 本轮针对角色主要数值、位置/时间及背包数量增加写档前的有限值/安全整数检查。测试脚本会模拟异常值并确认原存档不被覆盖；它不是全量数值防膨胀方案，也不检查所有世界和 NPC 字段。
5. 连续拖动脸宽、下颌、下巴等滑杆并转身，观察预览是否卡顿；头部轮廓缓存已增加上限，但并不代表已达到集显性能目标。

## 衣物物理与遮挡检查

运行 `npm run test:character-physics`：覆盖远景、暂停、速度尖峰、衣摆长度，以及 3 种搭配、8 种动作、8 个方向和混合时间步的数值与可见性冒烟测试。这不是遮挡正确性或无穿模的自动证明。

人工检查：在衣橱选择广袖、披风、长裙、发带、发簪与背饰，旋转正面、侧面、背面，分别查看站立、行走、奔跑、施法、打坐、飞行、受击和闪避；重点观察袖子与躯干、衣摆与腿、披风与武器、头发与面部的前后关系。快速换装、移动后切回带披风的衣服，观察是否突然拉出长线；改变缩放或帧率后检查抖动和跳变。记录异常搭配、动作、方向及截图。

当前布条是屏幕空间二维链，部件按整体深度排序，并非三维碰撞布料；跨越身体前后的衣物、极端动作与角度仍可能存在错误遮挡或穿模，需视觉验收与后续分片/遮挡方案，不能保证所有组合正确。

## 存档读取保护

运行 `npm run test:save`。读取前会检查地图、坐标、世界比例和部分关键数据结构；压缩档会检查截断、无效引用及 64 MiB 解压长度上限。最近存档选择会跳过损坏的档位。旧格式可缺少后来加入的可选字段，但并未对所有历史存档进行兼容性认证。读档后续子系统仍可能抛错，当前不是完整事务回滚或全量 schema 校验；请在测试前导出备份。

人工测试：另存一个档并导出备份，移动、更换装备后读取，检查位置、时间、境界、背包与外观；有其他地域档时测试跨图读档。多个档位分别保存后验证继续游戏选择最近有效档。不要直接修改或删除唯一存档来测试损坏档。

## 战斗数值与持续伤害

`npm run test:combat-safety` 检查现有人界境界倍率、主要直接命中入口、部分护盾数据、NPC/召唤物受击及持续伤害过期结算。持续伤害只计算状态实际剩余时间，长帧不再按整帧多扣；异常数字会在已覆盖的入口被拒绝。其他模块直接扣血、治疗、模组副作用和全部护盾路径尚未统一或全面验证。

人工测试：备份存档后，分别使用普通攻击与火、毒技能，观察对敌人和角色的伤害；测试护盾完整吸收及破盾后溢出、NPC 混战和召唤物受击。留意燃烧/中毒到期时是否突然多扣血，以及正常技能是否无故不造成伤害；记录境界、技能、护盾状态与复现步骤。

## 程序化物品图标

背包等使用 `ItemGlyph` / `itemIconURL` 的原版物品图标改为程序绘制：法器沿用现有画笔造型，灵草、花果、丹药、瓶、矿、妖丹、符箓、卷轴及杂物使用程序化 SVG 原型。按类型、字形和品阶自动选择；物品定义可选 `visual: { shape, color }` 指定原型和六位 RGB 色。模组显式注册的图标仍优先，可能是模组自带图片。旧图标素材与其他绘制路径仍存在，尚未实现全游戏纯程序视觉或角色装备通用系统。

运行 `npm run test:item-icons`：检查全部物品定义、十类原型的栅格化、颜色输入与模组优先级。人工打开背包、商店、炼丹/炼器、功法卷轴和获得法器界面，检查小尺寸可辨识性、品阶配色及图标与物品名是否合理；如有不匹配请提供物品名称与截图。程序图标为同类造型复用，并非逐件原著造型。

## 法器程序外观数据

法器的 `art.look` 可选指定 `shape`、`c1`、`c2`（六位 RGB 色）与 `glow`（0–255 的 `R,G,B`）；缺失或不合法的字段回退到原有专属外观或类型默认值。背包图标、法器动作、装备护盾绘制与人物遁具使用同一套解析；不是所有特效、人物手持/背负或装备槽都已接入通用系统。

`npm run test:artifact-visual` 覆盖默认与自定义外观、颜色校验、图标/动作映射、变化后的缓存更新和飞舟八方向绘制冒烟。人工可检查已有剑、护盾、飞舟和双翼：对比物品图标与使用、飞行时的颜色和造型，转向时注意遮挡；新自定义造型及模组兼容还需实际玩法和视觉验收。

## 装备在人物上的外观（首批）

衣橱「衣裳 → 装备外观」可选择显示已装备的甲和靴；默认关闭，旧存档保留原衣橱显示。开启后，外甲/披风占用衣橱外罩，靴子使用装备配色；卸下或关闭后恢复衣橱外观。贴身软猬甲默认不显示。该选项只改外观，不改数值。物品的 `art.wear.visible` 可关闭显示，`art.wear.color` 可指定六位 RGB，未指定则取法器主色。

`npm run test:equipment-appearance` 覆盖开关、装备槽、甲/披风/靴、内甲、无效数据、缓存与 80 次不同动作方向绘制冒烟。人工测试：装备皇鳞甲或血色披风及靴子，开启选项，转身并分别跑步、施法、打坐、飞行；换甲、卸甲、关闭选项，保存读取后确认外观和装备属性。特别关注衣袖/披风遮挡。当前接入普通主角、衣橱预览、元婴及其肉身、战斗残影与诱饵；其他特殊绘制和具体装备独有造型仍未全部接入，不保证没有穿模。

`npm run test:ghost-physics` 检查残影和诱饵绘制不会改动本体的布条、弹簧、姿势及位置，并检查元婴绘制响应装备外观开关。人工可装备披风与发带，开启装备外观，使用遁术/诱饵及元婴出窍，观察本体和残影是否一致、布料是否被残影拉走；再关闭装备外观、切换装备并读档复核。性能与全部视觉遮挡仍需真实设备实测。

### 存档码与卷宗导入

存档码和卷宗取回都先预检，再写入存档三并读取；成功会覆盖存档三，操作前会明确确认。预检不通过不写入，读取失败会尽力恢复原存档三，若恢复失败会明确提示。读取仍不是完整运行态事务，失败后运行态可能部分改变，应重新加载页面并以备份恢复；存储被禁用或配额不足时不能保证回滚。损坏存档不会再被误标为「空」，覆盖损坏档需额外确认。

自动测试 `npm run test:save` 覆盖预检失败、加载失败、空档及已有档的恢复、存储错误、恢复失败、真实读档入口和模拟跨图切换。人工测试前先导出多份备份：在有存档三时尝试无效存档码、再取消导入，确认原档仍在；然后导入有效存档码检查位置和角色数据，有条件时另测跨地域。云卷宗取回也应先备份目标档；自动测试没有访问真实云服务或真实浏览器重载。

## 背包和坊市数值

`npm run test:inventory-safety` 覆盖异常数量、灵石安全整数上限、巨量批量扣除、真假货、读写档总量校验以及坊市买卖。数量仍使用 JavaScript 安全整数，同种物品跨堆叠总数最多为 `Number.MAX_SAFE_INTEGER`；超过时拒绝入袋，不是无限数值体系。内部 `removeItem` 现返回实际移除数量（不再创建逐件年份数组），现有项目内调用未依赖旧返回值，外部直接导入该内部函数的扩展需适配；模组公开的 `takeItem` 仍返回布尔值。

坊市购买前检查库存、价格和入袋空间；出售前检查价格与灵石容量，不允许以已鉴定假货凭空换灵石。其他任务、拍卖、NPC 交易、宗门资产等尚未全面改为原子交易，某些发奖调用未处理入袋失败；达到极限时不要继续游戏，应备份并反馈。旧档如果同种物品的跨堆叠总数超过安全整数会被拒绝读取，历史存档兼容尚未全面验证。

人工测试前备份：坊市买药、出售材料、购买假货并鉴定、检查库存与灵石变化；在丹药和灵石不足时确认交易不会发生；另做采集、炼丹、任务领奖、保存读档回归。

### 修炼与消耗数值回归
运行 `npm run test:cultivation-safety`：覆盖异常修为、感悟池与瓶颈、模组经验钩子、冲关数量、时间、满背包催生及已鉴定假丹。建议备份存档后，在游戏内检查打坐加成跨小境界和抵达瓶颈、奇遇感悟、正常服丹和墨露催生。模组经验 API 现返回实际入账量，不再返回请求量。秘境古碑、前世碑及两个骗局选项已改为统一感悟结算；其奖励受感悟池约束，满瓶颈时可能为零。突破钩子取消不会扣除本体丹药，钩子自身的副作用不会回滚，其他奖励与背包操作仍非全量事务。

运行 `npm run test:progression-integration`，覆盖真实事件选项、晋阶提示、瓶颈/封顶及模组取消大小突破。人工测试建议检查秘境古碑与前世碑、孩童与洞府骗局的实际提示，以及正常突破和模组取消突破。

### 炼制与宗门收支
运行 `npm run test:inventory-transactions`：检查配方重复材料累计、炼制成功入袋失败时不扣材料、不计时间和次数，炼器失败主材保护、特殊剑组、宗门俸禄及重复任务交付。背包交换仅覆盖已接入的入口；奇遇、NPC 交易等尚未全部接入。事件监听器在背包和炼制状态提交后收到通知，但其自身副作用不在事务回滚范围内。

### 拍卖成交
`npm run test:auction-settlement` 覆盖金额越界、灵石不足、拍品数量溢出和重复/重入成交。拍卖成交使用背包交换；竞价过程的江湖托等其他副作用不属于该事务。

### 悬赏与 NPC 交易
`npm run test:reward-barter` 覆盖赏金暂存、游戏存档读取后保留、重复/重入领取、假悬赏后果，以及以物易物和诚实出售的库存、真假格子和溢出检查。赏金无法入袋时会暂存，之后可在任意悬赏榜领取。NPC 以物易物现在扣除实际货槽库存，未鉴定假货保留其属性。其他 NPC 奖励与交易入口仍未全面事务化；这些测试也不能代替真实浏览器交互验收。

### 坊市与卖假丹
`npm run test:trade-consistency` 覆盖坊市库存及缓存预留、真假货、宗门贡献、同 ID 净变化，和卖假丹识破/成功、溢出回退及重入。坊市配额回调与其他模组侧副作用不属于背包事务；真实浏览器交互尚待统一验收。

### 程序化地表画材
`npm run test:procedural-ground` 检查 15 层可重复、可平铺的程序纹理、均值、分片生成与模拟 WebGL 上传；秘境原画材不可用时的地面回退也复用程序纹理。主地表仍由 WebGL 程序着色器绘制，画材生成期间使用原有纯程序地表；生成工作分 480 次调度，但耗时随设备而异，纹理最终上传及地表重烘仍可能造成卡顿。此测试不是真实 GPU、视觉或帧率验收。旧地表素材文件暂保留在仓库但已移除运行时引用；其他建筑、秘境画材及视觉资源仍未全面替换，秘境现有关闭开关保持不变。

### 程序化环境动物
`npm run test:procedural-wildlife` 检查 19 个动物或姿态键的像素输出、变换和画布状态、缓存复用，以及真实世界实体的静止、移动、起飞和鸟群绘制冒烟。原有动画主要通过整体平移、旋转和伸缩表现，不是完整的肢体骨骼动画；造型为简化程序轮廓。19 张旧环境动物图片不再被该绘制路径引用，但素材文件暂保留。动物比例、动作、场景融合和实际设备性能仍需最终验收。

### 城镇铺装与地饰
`npm run test:town-ground` 检查 15 种程序铺装 / 地饰、缓存与缩略、异常平铺参数、河道裁剪，并通过 `Renderer.drawLocGround2` 冒烟绘制天南、乱星海、大晋各一处实际集镇或岛屿布局。原 15 张铺装地饰图片已脱离运行时引用，旧文件暂保留；城池和宗门已有的代码绘制路径未改动，其他建筑、摆件仍有外部画材。材质按需生成且缓存，真实浏览器中的风格、接缝和高密度场景性能仍需统一验收。

### 集镇程序摆件

### 渲染排序与 WebGL 上下文恢复
世界对象分桶排序后，桶内再按 y 稳定排序，避免相近深度物件顺序错误；WebGL 上下文丢失时将已有 Canvas2D 回退帧复制到可见画布，恢复时重建资源、重置纹理与 GPU 查询状态并请求完整重画。渲染器销毁也移除窗口监听和 ResizeObserver。`npm run test:render-lifecycle` 覆盖排序一致性、回退画布呈现及模拟恢复/失败；这不等于真实 GPU 丢失恢复已验证，也不意味着世界对象已改成原生 WebGL 绘制。需要在真实浏览器测试恢复、遮挡、缩放和性能。

`npm run test:render-lifecycle` 用模拟 GL 验证氛围画布重绘版本、尺寸、画布对象和上下文恢复后的纹理上传；版本未变化时不重复上传。尺寸不变的重配置不再清空氛围和 UI 画布，尺寸变化会强制下一帧重画。模拟测试不证明真实 GPU 吞吐量或稳定帧率；仍需在集显、独显及多分辨率实测，同时检查切入秘境、恢复和缩放视觉。

### 秘境分块缓存与地表重试
秘境底图按层记录色块回退状态，画材就绪后各层分别失效重烘；分块采用最近使用顺序，非可见缓存目标上限 32 块，可见块超限时保留，向下楼梯清除旧层底图而不改变游戏状态。程序地表创建出错后重试复用已完成画布。`npm run test:procedural-ground` 覆盖多层失效、缓存淘汰、画布创建失败重试；未测真实浏览器显存、长时间行走时重烘成本及切层效果。

### WebGL 地表与画布上传异常恢复
宏观地形的两张纹理全部上传成功才切换，JS 异常时释放新资源并保留旧地形；画布上传异常时恢复像素解包状态并使相关纹理失效，下一次重新上传。`test:procedural-ground` 和 `test:render-lifecycle` 覆盖模拟异常、清理、重试和恢复数据。此处仅处理会抛出的 JS 异常，不能检测通常只通过 WebGL 错误状态报告的驱动失败，也不保证异常发生当帧可自动继续绘制。

### 极远景首阶段与战斗名牌
GPU 地表可用且缩放低于 0.045 时进入极远景，不再扫描或生成树、山和小装饰，使用 GPU 宏观地表颜色作为背景；回到 0.055 及以上恢复详细装饰分帧扫描。地表不可用时不进入此模式，仍走原 Canvas 分块路径。境界和战斗逻辑不受此项影响。此阶段尚未建立山区轮廓/森林区域摘要，极远景会暂时缺少独立山峰、瀑布和树冠；切换也未做渐变。

战斗名牌在缩放远于 0.35 时按屏幕网格抑制重叠，锁定目标和首领优先，文字投影尺寸保持约 12 CSS 像素。隐藏单位仍遵守原有可见性；已增加目标聚合数量与点击选择，仍未实现屏幕边缘指示或完整碰撞避让。`npm run test:far-view` 覆盖滞回、地表回退、优先级和 Canvas 文本尺寸；浏览器实际渲染与性能待验。

### 极远景宏观地理与地点简化（后续）
极远景按原有地域山脉、河流和道路中心线生成程序路径摘要：每帧最多处理 4 条、每条最多均匀抽取 64 点，路径分三类缓存并在缩放状态下复用；底色仍为 GPU 宏观地表。远景地点改画屏幕尺度的小方印，已探索地点和原本就公开的大地点可见，不生成其城镇布局、建筑、灯火或炊烟；大地点仍显示原名牌。此摘要是中心线近似，**不是**原始细节的精确替代，地表原有线段上限也未移除；超长弯曲道路抽样可能偏离，路径总绘制成本仍与地图道路数量有关。范围摘要逐步出现，暂未做交叉淡入。Canvas 路径与分帧用 `npm run test:far-view` 验证；真实地图视觉、遮挡、上传开销及集显帧率需浏览器实测。

### 远景战斗标记与指针

### GPU 地表河路候选空间索引
针对地表更新时的道路、河流全表扫描，增加按源数组身份重建的 4096 世界单位网格索引；每帧各索引最多推进 64 段并以约 0.6ms 为目标（单段不可中断），超长线段单独保守检查。未完成、超大视野或候选过多时退回原顺序全表扫描；候选排序后仍用原精确裁剪，保持相同先后及现有 256 段上限。`npm run test:segment-index` 包含 300 组随机与全扫描对照、超长段、宽视野退回、索引替换和真实 Renderer 数据打包对照。**这一步没有解除 256 段截断**，且假定地形线段变动时替换数组而非原地修改；实际地图帧耗、建索引开销、纹理渲染与视觉仍待 GPU 实测。

### 双圈神识：第一版
外圈继续用 `senseRadius`；精细圈为 `min(外圈, max(650, min(1600, 外圈×0.6)))`，距离随外放、敛息和环境压制计算。大地图和秘境中，生灵、战斗单位和 NPC 使用精细圈进行可见性裁剪；玩家精确点击、Tab/自动锁定、常规远程投放距离限制在精细圈内。外圈特效仍使用平滑后的外圈，后期记忆遮罩使用精细圈。外圈信息面板每 0.5 秒从**当前已活跃**的战斗敌人和 NPC 汇总方向、种类、数量、最近距离（世界单位/30 丈），不包含姓名和血量；隐藏、死亡、友军、随行者等被排除或按发现条件判断。此阶段不会因外圈提示生成新实体，也不停止外圈实体的游戏逻辑；尚未覆盖全部事件、采集点或未激活 NPC，没有完整空间查询/后台模拟，也不是所有特效与地图标记都已迁移到双圈。精细圈变小会影响既有战斗体验和旧存档，需实机平衡；画面显示、UI 遮挡、秘境流程和设备性能尚需浏览器验证。

### 双圈补充：已知机缘与地图
- 外圈雷达只读取当前缓存中、存档标记已发现且仍可用的机缘，汇总为机缘气息；不生成格子、写入发现状态或生成守卫。缓存被清理或重载后可能暂不显示，不能视为完整的已发现地点索引。采集点、事件尚未接入。
- 机缘绘制格子查询先裁剪到精细圈包围盒；大地图敌人详情限制在精细圈并遵守隐匿规则。大小地图实线为外圈，虚线为精细圈。原机缘更新的外圈发现与守卫生成逻辑暂未调整。
- `npm run test:site-render-scope`、`npm run test:sense-signals` 覆盖查询边界、只读及聚合；真实浏览器视觉、区域切换、平衡和性能仍需验证。

### 收敛与信息圈分离
- `awarenessRadius` 只供外圈显示和只读雷达使用：原始距离 4000 以下不压缩，以上渐近 12000，外放及区域压制再乘算；收敛时等于精细圈。特殊压制与外放仍会影响精细圈，但收敛本身不会缩小精细圈、精确锁定或普通施法距离。
- 原 `senseRadius` 暂作兼容的玩法作用范围，仍影响生成、迷雾、机缘、元婴等，收敛对其原有作用未全部迁移。信息圈变大不扩大它们；雷达仍只报告活跃实体和已缓存已发现机缘，不能视为完整远距世界扫描。被动隐藏敌人与隐匿词缀敌人不报告，外放可探到前者。
- 神识外圈特效渐变跟随信息圈，草动画仍以精细圈为准。自动化覆盖真实属性 getter 的收敛/外放/压制组合、增长曲线、锁定和隐匿过滤；画面、密集场景性能和高境界平衡需真实设备验证。

### 精细发现与已知奇遇外圈摘要
- 野外机缘及随机奇遇的新发现提示由精细圈触发，残图藏宝点的发现距离也改用精细圈；外圈变大不提前显示名称、标记或详情。机缘扫描同时覆盖原守卫活动范围和精细圈；守卫生成与清理仍沿用原玩法半径，避免改变重要生态逻辑。
- 外圈可汇总当前仍存在、已经发现且未结束的随机奇遇，只显示「奇遇气息」及聚合方向和距离；读取不生成或修改事件。未发现事件不显示。奇遇原有过期/距离清理策略不因外圈变大而改变。
- `npm run test:sense-discovery` 用真实更新方法验证外圈不提前发现、收敛时精细圈仍发现、只读聚合；采集点仍未接入，机缘仍仅限已缓存对象。显示与平衡仍需浏览器和设备验证。

### 已观察采集点与机缘短期记忆
- 外圈新增灵物气息：仅记住本次会话实际进入视口、精细圈且满足绘制可见条件的采集点；只显示聚合方向、数量与距离，不显示品种或珍稀度。已采集未重生的节点不显示，按现有再生日期恢复；读档清空这份记忆，切图重载也会清空。

### 常态与耗法外放的信息范围
- 常态信息半径 = 精细半径 +（完整信息半径 − 精细半径）的 25%；当完整半径小于精细半径时，两者重合。开启神识外放后达到完整信息半径，停用或法力不足时回到常态；敛息仍收至精细圈。精细圈本身仍按既有外放和区域压制规则变化，不受敛息缩小。
- 完整信息半径沿用 `450 + 55√神识`（无神识为 380），天衍诀系数 1.35，4000 以下不压缩、以上渐近 12000，之后施加区域压制；信息圈不再额外乘 1.4。外放原有的 1.4 倍仍用于兼容玩法作用半径，而非信息圈。很低神识时完整信息半径与精细圈可能重合。
- 外放起手扣 0.1 法力、持续扣蓝；修正心境回血加成在外放/催动遁光时仍回蓝的问题。旧版说明中的信息范围 ×2/×1.4 文案已更正。
- `npm run test:sense-range` 覆盖实际外放开关、法力耗尽、敛息、低法力、不同神识及区域压制。当前完整信息半径是有软上限的游戏平衡曲线，不是无限距离，也不代表雷达能生成或探测所有远程对象；真机性能与数值体验仍需验证。

### 已知机缘的分帧恢复
- 读档后，游戏更新逐步扫描信息圈附近的格子，只对当前地域存档中 `seen` 的格子重建机缘并放入有界会话记忆；不会写入发现状态、发送发现提示或生成守卫。雷达 UI 依然只读。
- 每帧最多检查 16 格、其中最多重建 2 个未缓存的已发现格；单次地形采样不能中断，因此这不是严格的毫秒上限。位置跨格、范围分档、存档或地域变化时重新开始；敛息使外圈与内圈重合时暂停恢复。
- 新开局会清理机缘会话记忆及恢复任务，避免前一局内容残留。恢复是渐进的，移动很快时或等待扫描时，远处已知机缘可能暂时不显示；采集点仍只记本次实际观察。

### 地表河路线段来源截断改善
- 之前 Renderer 在交给 GPU 分块前就把整片地表候选截断到 256 段，使后续按图块细分无法找回线段。现在来源与单块上限分开：单次来源按原顺序最多收集河段、路段各 8192 段，动态打包；GPU 图块仍最多 256 段，使用既有递归细分。
- 如果来源超过 8192，或极密集图块细分 3 层后仍超过 256，仍会安全截断（不会写坏其他纹理行）；性能信息里的“线段截断 源/块”展示本帧对应次数。该方案改善普通的大视野截断，不声称已完全消除极端截断，也不保证性能不受影响。
- `npm run test:segment-index` 对照有/无索引的 400 段来源，使用模拟 GL 实际走过 Ground 分块、纹理打包，确认末尾线段可上传及极密场景安全截断；未在真实 GPU 比较画面或帧耗。地表纹理、渲染生命周期和 GL 回归测试通过。

### 密集地表图块裁剪优化

- `npm run test:segment-index` 对 300 组随机子块分别对照全扫描，覆盖两种线段及分块上传控制流；这是算法和模拟 GL 验证，不是实际帧率或真实 GPU 画面证明。每个首层图块仍需扫描来源，密集场景还会分配候选数组，实机收益及内存开销有待测量。
