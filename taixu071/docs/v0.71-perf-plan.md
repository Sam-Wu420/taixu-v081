# v0.71 极致性能方案（渲染管线 + 远景 LOD + 生态刷新）

> 目标：不是"稳定 60"，而是**把可变成本压成常数**——场景里有多少对象都不再影响帧时间，
> 剩下的只有"像素成本"，而像素成本可以靠渲染缩放线性调。
> 验收线：1080p 独显稳定 **144fps**（1% low ≥ 130），集显 1080p 稳定 **120fps**，
> draw call ≤ 8，每帧上传 ≤ 0.3MB，JS 世界提交 ≤ 0.5ms，GC 停顿 < 1ms/分钟。

---

## 0. 现状基线（先把账算清楚）

| 项 | 现状 | 位置 |
|---|---|---|
| 世界怎么画 | Canvas2D 逐对象光栅化 → offscreen canvas | `world/render.ts` `this.canvas.getContext('2d')` |
| 怎么给 GPU | **整张** `texSubImage2D` 上传 | `gl/stage.ts:402 upload()` |
| 1280×800 dpr1.5 上传量 | 1920×1200×4B ≈ **9.2MB/帧**（60fps = 550MB/s） | 同上 |
| 地表 | 已经是 GL（全屏三角形 + 线段瓦片） | `gl/ground.ts` |
| 后处理 | 已经是 WebGL2（4 个半分辨率 RT + 泛光） | `gl/stage.ts` |
| 单件成本（实测/估算） | 角色 0.41~0.55ms、树 0.012ms、草 0.008ms、山 0.03ms | `tools/bench-lod.ts` |
| 世界尺寸 | 300,000 × 210,000 世界像素（MACRO 1000×700 ×300） | `data/world.ts` |
| 神识半径 | `450 + 55·√sense` → sense 10 万 ≈ **17,800px** | `world/game.ts:647` |
| 当前 zoom 下限 | 0.22（远视角放不开） | `render.ts` |

结论：**CPU 光栅化 + 整帧上传** 是当前天花板，LOD 只能让近处好看，救不了帧率。

## 1. 总体架构：三档视角 + 一条 GL 管线

```
近景 (zoom ≥ 0.22)：对象级 —— 实例化精灵 + 特写角色矢量层
中景 (0.22 ~ 0.08)：分块底图 —— 512² 静态块 + 活跃对象 + 点
远景 (0.08 ~ 0.02)：金字塔层 + 符号层 —— 地形缩略 + 图标/名字
```

三档之间用 **20% 宽度的 alpha 交叉带**过渡（`lod.ts` 的 `fade`），并给细节权重加
**时间速率限制**（每帧 ≤ 4%）+ **5% 迟滞**，保证来回缩放不闪、不呼吸。

每帧固定提交：

```
地面(GL) + 精灵实例(GL, 1~3 calls) + 角色层(1 张小纹理) + 符号/文字(GL) + 后期(GL)
```

## 2. P0 地基（1~2 天）

### 2.1 帧预算调度（保底，先做）
`world/frameBudget.ts`（新增）：

```ts
export class FrameBudget {
  constructor(public targetMs = 8.3) {}
  /** 每帧重置；返回本帧还能花多少毫秒 */
  begin(emaMs: number): number;
  /** 提交一个对象前问一句：还画得起吗（按优先级排队，用完了就不再画低优先级） */
  allow(priority: number, costMs: number): boolean;
}
```

- 优先级：玩家 100 · 锁定目标 95 · 宗门/城镇 80 · 敌对 70 · 稀有 50 · 普通 20 · 装饰 5；
- 实现细节：按优先级降序取，累加 cost 直到超预算；未入选的对象交给"符号层/点层"降级表示；
- 与已有 `lod.ts` 的 `noteFrame(ms)` 自适应 `bias` 联动：连续 2 秒 < 65fps 就把 `bias` 压低 0.05。

### 2.2 脏矩形上传（当天见效）
`gl/stage.ts`：

```ts
upload(tex, cv, premult, isScene, dirty?: { x: number; y: number; w: number; h: number })
// same 尺寸且 dirty 存在 → gl.texSubImage2D(gl.TEXTURE_2D, 0, x, y, w, h, gl.RGBA, gl.UNSIGNED_BYTE, cv, …)
```

`world/render.ts` 每帧收集脏区：
- 角色/特效：各自包围盒并集；
- 新出现/消失的对象：其旧/新包围盒；
- 天气/水面全屏动画：退化为整帧（此时改用 P3 的分块底图后不再出现）。

**验收**：静止/走路时上传 ≤ 0.3MB；FPS 面板"世界层上传"分段 ≤ 0.4ms。

## 3. P1 精灵实例化（3~5 天，最大杠杆）

### 3.1 图集
`gl/atlas.ts`（新增，已有 `gfx/sprites.ts` 的烘焙产物直接复用）：

- 统一 **2048×2048 RGBA** 图集，4 张（树/山/建筑/杂项）；LRU 常驻；
- 打包：按高度排序的 shelf packing；每块 padding 2px 防渗色；
- 网格数据：每帧把可见精灵写成 instance buffer（`Float32Array` 预分配 8192×8：x,y,w,h,u0,v0,u1,v1）。

### 3.2 实例化绘制
```glsl
// vertex
layout(location=0) in vec2 aPos;     // 单位四边形
layout(location=1) in vec4 aInst;    // x,y,sizeX,sizeY
layout(location=2) in vec4 aUV;      // u0,v0,u1,v1
layout(location=3) in vec4 aTint;    // r,g,b,alpha
```
- 一次 `drawElementsInstanced`，按「同一张图集 + 同一个 shader」分批，实测 5000 棵树 = 1 个 draw call；
- 风摆：在 vertex shader 里按 `time + 实例相位` 偏移 top 顶点（替代 CPU 端 `drawTree` 的 setTransform）；
- Y 排序：GPU 端不需要精确，把实例按 y 写入顺序即可（同一图集的实例顺序 = 绘制顺序）。

### 3.3 CPU 侧
- `render.ts` 的 `Drawable[]` 改成两个预分配 typed array（近处对象 / 装饰），
  排序用 **计数排序**（按 y 分桶，桶宽 = 32px），避免每帧 `Array.sort` 的分配与比较开销；
- 剔除：视锥 + `occ` 遮挡 + 距离；不可见的对象**一条指令都不提交**。

**验收**：`gl.drawCalls ≤ 8`；`R·收集山树` ≤ 0.3ms；密林 scene 帧时间从 ~20ms 降到 ≤ 6ms。

## 4. P2 角色分级（2~4 天）

| 屏上高度 | 画法 | 成本 |
|---|---|---|
| > 40px（通常 ≤ 3 人） | 现有 Canvas2D 矢量画进 **256² 离屏纹理**，仅在姿态变化帧上传 | 0.55ms + 0.26MB 偶发上传 |
| 12~40px | 预烘帧图集（朝向 16 × 姿态 8 × 服装哈希），实例化 | ~0.02ms/人 |
| < 12px | 2px 点（按重要性配额，≤ 300 个） | ~0.005ms/人 |

要点：
- 帧图集烘焙在 idle 回调里分批（每帧 ≤ 2ms），避免卡顿；
- 近景主角仍走矢量，保证特写不变形；量化只发生在小尺寸；
- 点层用一张 8×8 白点纹理 + 实例化，颜色区分敌我/宗门。

**验收**：100 个 NPC 同屏，世界提交 ≤ 1ms。

## 5. P3 地形 mip + 远景金字塔 + 符号层（5~8 天）

### 5.1 地形
- `gl/ground.ts` 的瓦片纹理生成 `gl.generateMipmap`（或手工 3 级），远景 `minFilter=LINEAR_MIPMAP_LINEAR`；
- 地表可按 `renderScale` 渲到半分辨率再上采样（4K 下省一半）。

### 5.2 植被密度层（关键：树消失后林子还在）
- chunk 烘焙时统计该块 decos 的树/草密度 → 一张 **64² 的低频色块**（森林深绿、草甸浅绿、荒地土黄）；
- 远景（树 < 8px 不再逐棵画）时，这层色块承担"看起来有林子"；
- 数据来源：`terrain.getDecos(chunk)` 一次统计，随 chunk 缓存。

### 5.3 金字塔层
- 层级 `L = clamp(round(log2(1/zoom)), 0, 5)`；每层由下一层 2×2 降采样（离屏 blit）；
- 只保留视野内 32~64 块（256²，LRU），生成放在 idle；
- 失效：季节/地形变化重烘；昼夜用整体色罩，不重烘。

### 5.4 符号层
- 城镇/宗门/秘境/灵脉/妖兽群/门人/玩家 → 图标 + 名字（已有 `labelCache`/`plaqueCache` 扩展成图集）；
- 数量按重要性配额（≤ 200），重叠时优先级高者胜；
- 远景时这就是主要信息（"神识视野"）。

**验收**：zoom 0.036（神识 10 万）帧时间 ≤ 5ms；放开 zoom 下限到 0.02。

## 6. P4 生态与刷怪改造（和渲染同等重要）

### 6.1 症状与根因
现状 `world/combat.ts:1213 spawnTick()`：

```ts
const R = g.senseRadius;
const dist = clamp(R * 1.05, 520, 1500) + rand(0, 300);
// → 在"神识半径外一点点"凭空 new Enemy 并 push 进 enemies
```

问题：
1. 只避开"神识圈"，没避开**屏幕视野**——视野比神识大时（或神识被扩大后）就"眼睁睁看着刷出来"；
2. 刷新是 `new` 出来的，不持久：走开再回来，怪物全部消失/重刷，位置也不连续；
3. 数量上限 `cap = 3 + dz.k*0.8 + night*2 + tide*6` 只按"身边 2800px"统计，远端无人管。

### 6.2 目标：生态账本 + 休眠/唤醒 + 迁徙

**数据结构**（`world/ecology.ts` 新增）：

```ts
type EcoState = 'hibernate' | 'active' | 'dead';
interface EcoBeast {
  id: number; defId: string; chunk: [number, number];
  x: number; y: number; realm: number; stage: number;
  state: EcoState; aggro: boolean; hpPct: number;       // 休眠时只存百分比
  patrol: { x: number; y: number }[];                   // 迁徙/巡游路径（可选）
  lastSeen: number;                                     // 上次离开视野的时间
}
class Ecology {
  /** 每 chunk 的生态槽：目标数量由危险度/地形/昼夜算出 */
  slots: Map<string, EcoBeast[]>;
  /** 视野外补员：只在不可见区域生成；不可行则推迟 */
  requestPopulate(chunk: [number, number], n: number): void;
  /** 玩家移动：激活进入"活跃半径"的休眠体，其余休眠 */
  updateActors(p: { x: number; y: number }, activeR: number): void;
  /** 把一只休眠体从 A 迁到 B（补员优先用它，而不是凭空生成） */
  migrate(e: EcoBeast, to: [number, number]): void;
}
```

**生成规则（硬约束）**：
1. 生成点必须在 **`visibleRect` 之外 + 200px 余量**，且不在任何角色/村落 200px 内；
2. 若玩家视野覆盖整个可生成环（极远视角），**不生成**，改为"从视野外沿走进来"：给一个 30~90 秒的迁移路径，走到视野边缘时按距离淡入；
3. 视角内**永不 new**：`spawnTick` 退化为"补员请求"，由 `Ecology` 判定是否允许；
4. 神识扩大 ≠ 变出新怪：只把更多休眠体转为活跃（它们本来就在那里）。

**数量与性能**：
- 活跃上限 `ACTIVE_MAX = 64`（含妖兽/散修/追兵），超出按距离与敌意保留；
- 休眠体只做每秒一次、分批（每帧 ≤ 8 只）的低频 tick，不跑 AI；
- 休眠体不渲染；活跃体按 P2 的尺寸分级渲染。

**与渲染联动**：
- 远景点层显示的怪物 = `active` 且按重要性配额；
- 淡入：`fadeIn = smooth(distFromScreenEdge, 0, 120)`（世界 px），避免边缘突现。

**验收**：
- 连续行走 10 分钟，统计"新出现的怪物是否在屏幕内首次可见"→ 必须为 0；
- `enemies.length` 不随时间单调增长（有回收）；
- 远景视野里点数 ≤ 300，帧时间不因怪物数量变化超过 0.3ms。

## 7. P5 CPU 零分配与错帧（2~3 天）

| 项 | 做法 | 目标 |
|---|---|---|
| 每帧分配 | 对象池（instance/Drawable/特效）、预分配 typed array | GC 停顿 < 1ms/分钟 |
| 排序 | 计数排序（y 分桶） | 排序 ≤ 0.1ms |
| 更新 | 远处 AI/物理/动画 `cadence(k)`：每 N 帧一次、用累积 dt | 更新 ≤ 1.5ms |
| 脏标记 | 只有变化实体重算变换/动画/缓存键 | 免重复计算 |
| 字符串 | 名字/标签预烘（已有），运行时不拼串 | — |

## 9. 验收与测量

- `F3` 面板：`R·` 分项、`gl.drawCalls`、上传 MB/帧；
- `gl/stage.ts` 已接 `EXT_disjoint_timer_query_webgl2`：分「地表 / 上传 / 泛光 / 后期」；
- 新增 `tools/bench-frame.ts`：脚本化把 zoom 从 1.0 匀速推到 0.02 再拉回，记录 (zoom, 帧时间, 细节权重, drawCalls, 上传量)，输出 95 分位与"相邻帧细节变化 > 4%"的帧数（应为 0）；
- 三个硬指标：
  1. 1080p 独显：95p 帧时间 ≤ 8.3ms（144fps）；
  2. `drawCalls ≤ 8`、上传 ≤ 0.3MB/帧；
  3. 刷怪：行走 10 分钟，屏幕内首现次数 = 0。
