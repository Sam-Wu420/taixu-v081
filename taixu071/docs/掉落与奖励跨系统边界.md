# 掉落、奖励与装备跨系统边界审计

> 对应 `docs/人界改造_当前进度与后续计划.md`「后续任务 1」之跨系统边界核对。本文记录**已经实现原子/受保护语义**的链路，以及**客观上无法纳入单一事务的边界**，不做笼统兜底声明。

## 一、已实现整批原子结算或落地保护的路径

1. **背包原子事务（`cultivation.ts` `exchangeItemsWithCommit`）**
   - 所有消耗与产出先在深拷贝 `bag` / `equip` 上校验，全部成功后再一次性写回 `h.bag`、`h.equip` 与 `lastFakeConsumed`，之后才执行 `onCommit`（状态位 / 声望 / 冷却）与物品拾取通知。
   - 已覆盖：`sites.ts`（灵药王、前人遗骸、禁制石台、兽巢、山神庙、灵潭潜底、古战场、藏宝点）、`landmarks.ts`（一次性遗物、古修遗骸）、`mijing.ts`（宝箱与秘境灵草）、`happen.ts`（劫修买路、赌斗押注）、`cultivation.ts`（炼丹 / 炼器 / 指定格交易）。

2. **事件与探索奖励落地兜底（`game.ts` `grantOrDrop` + `exploreCheck` + `events.ts`）**
   - 主线/纪事大事件（`CanonEvent.reward`：赤霄禁地、鸿家堡、魔门入侵、归墟殿、陨魔谷、问仙令）与野外奇遇（天材地宝、灵草丛、救治/搜刮伤修、古修遗府、神秘摊主）、秘密地点首探（`exploreCheck`）先汇总成完整 `plan`，调用 `game.grantOrDrop(plan)`。
   - 先走 `exchangeItemsWithCommit` 尝试整批入袋；若背包满/上限拒收，则逐件尝试入袋，仍进不去的以 `{ blocked: true }` 写入当前界面的地面掉落队列（大地图进 `combat.loot`，秘境进 `mijing.loot`）并提示玩家「已落在脚边」。

3. **受保护地面掉落与重置 / 存读档隔离（`combatDropSafety.ts` + `savedDrops.ts`）**
   - 地面掉落更新使用快照 + `WeakSet` 防重入锁（`updateWorldDrops`）；回调中新建的掉落保留到下一帧，不会在当前帧清理阶段被误删。
   - 跨地域远行与存档按地域持久化 `savedDrops`；秘境掉落与大地图严格隔离。
   - `combat.reset()` 的五条业务路径已分别按「留在原地（`resetCombatKeepingDrops`）」与「随遗物入墓碑（`protectedLoot` → `onTrueDeath`）」保底。

4. **装备与背包一致性边界（`cultivation.ts` `syncEquipWithBag`）**
   - `h.equip`（`armor` / `shield` / `flight` / `boots`）仅保存对 `h.bag` 中法器 ID 的引用（穿卸不进出背包，不会因背包满而丢件）。
   - `removeItem` 与 `exchangeItemsWithCommit` 提交后自动调用 `syncEquipWithBag(h)`：一旦某件已穿戴法器的最后一格因炼化、交出或消耗而离开背包，对应 `equip` 槽自动清空；若事务中途失败回滚，`h.equip` 与 `h.bag` 同步保持原状。

## 二、明确无法单事务原子化的跨系统边界

1. **非背包副作用（经验、声望、公告、守卫刷怪）**
   - `exploreCheck` 惊动守护妖物（`spawnGuards`）、`CanonEvent` 完成后发放的修为/新闻/全局旗标（如 `ws.flags.yueHeld` / `ws.rep`）、以及 `happen` 中的仇怨/传闻，一旦进入 `resolve` / `onWin` 即生效；若物品进不了背包，会以**地面受保护掉落**保留物品本身，而**不会回滚**经验/声望/守卫生成。
2. **交易对话框开启期间的外部扣除**
   - `events.ts` 中的灵石购令（`shengxian`）、疗伤丹救伤修（`wounded`）、残卷摊主（`stall`）在选项点击回调内再次核验 `removeItem(...) === need`；若在对话框开启期间玩家因外部扣款/法力变化导致不再满足条件，只终止本次交易，不回滚先前已触发的事件状态。
3. **模组回调边界（`modx.emit` + `safeHookDrops`）**
   - 模组向掉落队列注入的物品受 `safeHookDrops` 限制（最多 1024 扫描 / 256 条、丢弃非法 ID、数量夹在 `[1, 9999]`）。
   - 模组若在回调中自行调用 `game.travel()` 切图、直接改写 `hero.bag` 或修改其他全局状态，游戏无法对模组内部任意副作用做事务回滚；切图前的检查点保存与秘境隔离仍保证已标记地面掉落不跨界混杂。
