# 宗门万人金字塔、百人战阵与全界域演化设计方案

> 本文档整理自架构设计与玩法探讨，作为后续分阶段落地的工程蓝图。
> **核心铁律**：战场、山门与大地图上的所有修士人物、宗门法袍、阵旗法阵与飞剑神通，**必须 100% 复用游戏现有美术资源与渲染管线（`drawCharacter` / `randomLook` / `SECT_ROBE` / `formationEffects` / `combatfx`）**，严禁另写简化火柴人、火柴点或替代几何简笔画充数。

---

## 一、设计目标与核心原则

### 1.1 还原原著宗门金字塔体量
以人界中等至大宗门为例，构建符合修仙界真实比例的金字塔结构：
- **底层（上万炼气）**：其中约 55%–65% 为炼气 1–5 层**杂役弟子**（后勤、不参战），约 35%–45% 为炼气 6–13 层**外门弟子**（可编入百人战阵与据点值守）。
- **中坚（数百筑基）**：内门与真传/核心弟子（约 150–450 人），担任据点队长、战阵**阵眼**与宗门中坚。
- **高层（约 10 名结丹 + 1–2 名元婴）**：掌门、执事、各峰结丹长老与镇派太上元婴老祖（天魔宗另含 1 名化神初期太上）。

### 1.2 性能与存档体量恒定
- **禁止**为上万名炼气弟子逐个建立 `NpcData` 对象或逐帧跑寻路/背包/AI。
- 无论玩家玩到第几年、未来开放到灵界还是仙界，全局常驻存档的真实 `NpcData` 控制在 **~200–400 名核心角色**内，避免存档膨胀与长跳卡顿。

### 1.3 美术资源零妥协（严禁火柴人）
- 战阵、山门与城镇出现的所有弟子，**必须全部使用项目既有的人物绘制系统**：
  - 造型与服饰：`src/gfx/character.ts` 的 `drawCharacter`、`randomLook` 配合 `src/data/sects.ts` / `src/world/npc.ts` 的宗门袍色 `SECT_ROBE`（`X_ROBE`），保证每个宗门有制式道袍、发冠、脸型与持剑/施法姿态；
  - 阵旗与阵法视觉：`src/gfx/formationEffects.ts` 已有的 `zf_flag_*`（五行/魔道阵旗）、`zf_dome`（光幕）、`zf_link`（阵纹连线）、`zf_eye`（阵眼）、`zf_activate`、`zf_break` 等；
  - 飞剑与神通：`src/world/combatfx.ts`、`src/gl/fx.ts`、`src/gl/batch.ts` 与 `src/world/artacts.ts` 现有弹幕、剑气、法宝光效。
- 性能优化依靠**“共享同宗门帧缓存 + 战阵逻辑合并 + WebGL 批量提交”**实现，绝不靠降低人物美术精度或换成火柴人来实现。

## 二、全界域分层模型（人界 / 灵界 / 仙界通用）

**重要前提**：结合 `src/data/worldHierarchy.ts` 的三界架构，**灵界与仙界同样完整保留从「凡人(0) → 炼气(1) → 筑基(2) → 结丹(3) → …… → 该界域极境」的全部境界**（例如灵界有凡人城池、炼气散修与结丹外门；仙界亦存在下界飞升的大乘修士作为仙宗杂役/外门）。

因此，不能用绝对境界 `realm >= 3` 一刀切，而应**按所在界域抬高真实数据门槛**：

| 界域（全境界保留） | 第 1 层：纯数字池（杂役 + 可战外门） | 第 2 层：种子按需现身池（中坚 / 阵眼） | 第 3 层：常驻真实 `NpcData`（核心骨干） |
|---|---|---|---|
| **人界**（凡人 ~ 化神） | 凡人 / 炼气（1–5 杂役 · 6–13 外门） | 筑基（数百人） | **≥ 结丹**（执事 / 长老 / 掌门 / 太上，约 12–18 人/宗） |
| **灵界**（凡人 ~ 大乘） | 凡人 / 炼气 / 筑基 / 结丹（杂役 & 外门） | 元婴 / 化神（数百人） | **≥ 炼虚**（炼虚执事长老 / 合体掌门 / 大乘老祖） |
| **仙界**（凡人 ~ 大罗） | 凡人 ~ 大乘（杂役 / 飞升预备） | 真仙 / 玄仙（数百人） | **≥ 金仙**（金仙长老 / 太乙掌门 / 大罗道祖） |

### 永久留表例外（不受第 3 层门槛限制）
无论处于哪个境界或界域，只要满足以下任意一条，立即保留或“转正”为永久 `NpcData`：
1. **原著与剧情具名人物**（如青霞谷的 `严化尘`、`柳卫娘`、`陆青崖`、`赵无忌` 等）；
2. **与玩家发生真实因果者**（`met` 且有 `favor / grudge / bond / ties`——认识、结仇、师徒、道侣、结义、受赠丹药法宝）；
3. **核心 NPC 婚育出的有灵根后代**（见下方“家族收束”）。

## 三、宗门数据结构重构：三层名册 + 杂役/外门分离

### 3.1 底层人口计数结构（替代全量下标数组）
在 `src/world/roster.ts` 中，每个宗门持久化结构 `ws.flags.ros[sid]` 改为轻量金字塔结构：

```ts
interface SectPoolState {
  // 第 1 层：底层海量弟子（只存数字，不建对象、不进死人ID数组）
  servant: { alive: number; cap: number };                 // 杂役池（如人界炼气 1–5 层）：后勤，不参战
  outer: { alive: number; injured: number; cap: number };  // 外门池（如人界炼气 6–13 层）：可进百人战阵
  // 第 2 层：中坚种子池（筑基/灵界元婴化神）——O(1) 分段区间 + 稀疏变更
  midCap: number;
  midDead: number[];        // 仅存阵亡序号（或压缩位图）
  midGen: Record<number, number>; // 阵亡后补位代数
  // 第 3 层：高层与转正角色直接在 NpcWorld.list 中以 sect + rank 维护，此处只记录席位映射
  topSeats?: Record<number, string>; // 席位下标 -> NpcData.id（含原著与新晋长老）
}
```

### 3.2 `roster.ts` O(1) 区间化改造
- 取消 `members()`、`summary()`、`pick()` 中 `for (let i = 0; i < def.n; i++)` 的全量线性扫描；
- `summary(sid)` 直接用各层 `cap - dead` **O(1)** 计算各境界与各职位的实时在世人数；
- 中坚种子池（数百人）在 UI 展开分页时，只对当前页的 `12–15` 个下标调用确定性种子函数 `member(def, idx, gen)` 生成展示信息；
- `pick(sid, n, realmLo, realmHi)` 直接在对应层次的索引区间里随机抽取可用席位。

### 3.3 杂役与外门的职责与流转
1. **杂役弟子（`servant`，人界炼气 1–5 层）**：
   - **严禁上前线**：常规宗门会战、据点抽兵、百人战阵绝不拉杂役送死；仅当护宗大阵已破、敌方兵临山门灭宗绝境时触发溃逃或被遣散。
   - **职责**：维持宗门灵田/矿脉基础产出；在山门外山/药园附近走近时，以普通同门 `Walker`/轻量化形象担任氛围陪衬。
   - **晋升**：在 `daily(days)` 闭式结算中，随时间推移按修炼速率自然有一批杂役突破至炼气六层，自动转入 `outer` 池。
2. **外门弟子（`outer`，人界炼气 6–13 层）**：
   - 唯一允许进入**据点轮值**与**百人战阵**的炼气兵源；
   - 外门死伤过多导致 `outer.alive` 见底时，宗门即使库房有钱也凑不出战阵，只能龟缩山门大阵等待杂役成长和下届升仙大会补员。

## 四、统一宗门职位体系（8 级制，打通三界与自建宗门）

统一合并目前 `src/world/worldstate.ts`（5 级 `SECT_RANKS`）与 `src/world/roster.ts`（7 级 `RANKS`）的冲突，建立全游戏唯一职位表：

| 等级 | 职位名称 | 人界境界门槛 | 灵界参考门槛 | 数据归属 | 核心职责与权限 |
|---:|---|---|---|---|---|
| 0 | **杂役弟子** | 凡人 / 炼气 1–5 层 | 凡人–筑基 | `servant` 数字池 | 杂务、灵田、**不参战** |
| 1 | **外门弟子** | 炼气 6–13 层 | 结丹–元婴 | `outer` 数字池 | 据点值守、**百人战阵士兵**；主角可入他人战阵随军 |
| 2 | **内门弟子** | 炼气圆满 / 筑基初中期 | 元婴巅峰–化神初中 | 种子池 | 据点百夫长、**担任百人战阵阵眼队长** |
| 3 | **核心 / 真传弟子** | 筑基中后期 | 化神中后期 | 种子池重点 / 熟人入 `npc` | 主力战阵统领、秘境带队、长老第一顺位候补 |
| 4 | **执事** | 筑基巅峰 / 结丹初期 | 化神巅峰 / 炼虚初期 | 重要席位入 `npc` | 坊市/执法/传功堂主事、大战先遣主将 |
| 5 | **长老** | 结丹全境 | 炼虚全境 | **全员真实 `NpcData`** | 宗门支柱（~8–12 人），督战、收徒、镇守山门 |
| 6 | **掌门** | 结丹后期 / 元婴 | 合体 | **真实 `NpcData`** | 一派主事，掌宣战/议和/政令；战死由长老继任 |
| 7 | **太上长老** | 元婴 / 化神 | 大乘 | **真实 `NpcData`** | 镇派底蕴（0–2 人），平时闭关，唯灭宗或盟战现身 |

- **容错降级称谓**：若某宗门长老、元婴战死绝了，允许由筑基真传/执事出任**「代理掌门 / 署理长老」**，职位保留但显示境界不足，让全服势力一眼看出该派青黄不接。
- **自建宗门（`src/world/mysect.ts`）同步接轨**：`s.ds[]` 仅保留主角重点培养的内门/筑基/结丹/有交情骨干；外门炼气与杂役改走 `s.servant` 与 `s.outer` 数字池（受灵脉殿与丹房等级影响招新速度），让自建宗门同样能派出数支百人战阵迎战大宗门。

## 五、灵根修炼速度、核心晋升与世界演化

### 5.1 灵根体系校准（`src/data/realms.ts`）
当前代码中天灵根（`2.0x`）与伪灵根（`0.5x`）只差 4 倍，且在 `majorChance()` 中对突破概率影响过小（仅约 3% 差距）。建议校准为更贴近原著的梯次：

| 灵根 | 修炼速度倍率 | 大瓶颈加成（筑基 / 结丹） | 原著生态定位 |
|---|---:|---|---|
| **天灵根** | `2.4x` | 筑基 `+20%` · 结丹 `+30%`（几乎无瓶颈） | 宗门重点真传，顺遂结丹的种子选手 |
| **异灵根** | `1.8x` | 筑基 `+12%` · 结丹 `+15%` | 斗法强横，宗门核心主力 |
| **真灵根** | `1.35x` | 筑基 `+6%` · 结丹 `+5%` | 内门中坚，有希望靠资源结丹 |
| **三灵根** | `0.85x` | `0%` | 苦修至中年拼一粒筑基丹 |
| **伪灵根** | `0.45x` | `-5%` | 无外挂/海量丹药极难筑基 |

### 5.2 主角与 NPC 算法「同源分流」
1. **统一突破入口**：废除 `src/world/npc.ts` `daily()` 中绕过灵根与丹药、纯靠固定概率 `[0, 0.4, 0.22, 0.12, 0.05]` 跳层的旧循环，全部收口到 `src/world/living.ts` 的修炼体系。
2. **共用底层参数表**：主角与核心实名 NPC **共用同一套 `REALMS.expDays`、`ROOTS` 倍率与 `MAJOR_BREAKS` 丹药加成**。
3. **推进方式分流**：
   - 主角走 `cultivation.ts` 的每日精确 `exp`、感悟池与历练门槛；
   - 核心 NPC（~200–400 人）在闭关结束时按 `(闭关天数 × 灵根效率) / expNeed` 结算进度，且**大境界突破必须真实消耗背包里的筑基丹/降尘丹/九曲灵参丹**（通过宗门贡献兑换、探险或玩家赠送获取），不再无丹瞎蒙成元婴；
   - 保留 `src/world/demog.ts` 的 `canAdvance()` 名额校验与界域上限限制。

### 5.3 核心空缺晋升链与家族自然收束
- **战死补位链（自下而上越来越难）**：
  - 炼气 `servant → outer → 种子池筑基`：随时间按比例与丹药产出稳步补位，但若 `outer` 池被大战打空，未来数年新晋筑基产出同步骤跌。
  - **结丹长老/掌门空缺**：优先从 `NpcWorld` 里**本宗已有交集或已入册的筑基后期/真传**提拔或在其破境时继任；若无现成者，再从种子池抽一名高资历筑基圆满弟子破境转正入 `npc` 表并播报传闻。
  - **元婴老祖空缺**：**绝不强行秒补**。老祖陨落后宗门进入真实的**“无元婴空窗期”**（持续数十年至上百年，外交紧张度上升），直到本宗某位结丹巅峰长老真正攒够机缘碎丹成婴，或沦为二流/被吞并。
- **核心 NPC 后代收束**：沿用 `living.ts` 现有的**自然寿元坐化 + 危险折损 + 高阶低孕率（`0.035 / (realm - 1)`，限 2 胎）+ 仅 40% 概率测出灵根**机制，家族血脉天然动态平衡；仅将 `npc.ts` 清理久远普通死者的阈值从 `860` 同步下调至 `~420`（始终保留原著人物、玩家有因果关系者）。

## 六、宗门大战：百人战阵机制与大场面渲染

### 6.1 「1 筑基阵眼 + 100~200 外门炼气」战阵数据模型
在 `src/world/sectwar.ts` 中，不再同屏刷新几十个独立散兵互砍，而是以 **战阵（`FormationUnit`）** 为基本作战编队：

```ts
interface WarFormation {
  id: string;
  sectId: string;
  side: 'ally' | 'foe';
  leader: Enemy;          // 真实 Enemy 实体（筑基阵眼队长 / 或结丹督阵）
  qiAlive: number;        // 当前阵中尚存的外门炼气弟子数（如 180）
  qiMax: number;          // 满编人数（100–200）
  radius: number;         // 阵型半径（随 qiAlive 收缩）
  shieldHp: number;       // 阵法合击护盾（与 qiAlive/qiMax 挂钩）
  charge: number;         // 合击蓄力进度 0..1
  pattern: 'arrow' | 'bagua' | 'circle'; // 锋矢 / 八卦 / 圆阵
  robe: string;           // 宗门道袍色（SECT_ROBE[sectId]）
  slots: Float32Array;    // 预分配的阵位偏移 (dx, dy, phase) * qiMax，零每帧对象分配
}
```

### 6.2 战斗计算（只算 1 个阵，不逐个算 200 个小兵）
1. **移动与 AI**：每帧只有 `leader`（筑基阵眼 `Enemy`）执行 1 次寻路、转身与仇恨逻辑；外围 100–200 名炼气弟子按 `slots` 偏移围绕 `(leader.x, leader.y)` 做统一朝向与迈步/掐诀动画，**CPU 成本为 $O(1)$**。
2. **合击齐射**：`charge >= 1` 时触发 1 次战阵合击——视觉上百人同时举剑/施法，射出成片同宗属性飞剑流光或合击灵柱，但伤害判定与弹幕物理**合并为 1 组扇形/波次弹道**（威力与密度随 `qiAlive` 衰减）。
3. **两种破阵打法**：
   - **斩首阵眼**：突入阵心直接击杀中间的筑基 `leader`；阵眼一死，战阵灵力反噬崩溃，外围残余炼气弟子立即四散逃离战场并淡出退场；
   - **群体洗地（AOE 破阵）**：玩家或高阶长老施放大范围神通（如大庚剑阵、五雷正法等）扫过战阵覆盖圆时，按「命中面积比例 × 伤害」直接批量扣减 `qiAlive`（一次清掉数十名外门弟子并触发批量阵亡粒子与退散），加速瓦解阵盾与合击威力。
4. **主角不同境界的参战定位**：
   - **炼气期**：受征召时编入己方某位筑基师兄的战阵内随军作战（享阵法庇护，点杀敌阵前锋赚战功）；
   - **筑基期**：解锁独立统率 1 座百人战阵（自带本宗外门炼气结阵跟随合击）；
   - **结丹 / 元婴期**：独当一面冲阵破阵、硬撼敌方结丹长老与护宗大阵。

### 6.3 渲染实现规范（严格使用游戏现有资源，严禁火柴人）
为了同屏摆出 **敌我各 2–4 座百人战阵（同屏 500–1,000 名修士对峙）** 且维持流畅帧率，按以下方式**直接复用项目已有渲染能力**：

1. **离屏预烘「制式弟子动作帧」（源自 `drawCharacter`）**：
   - **严禁**画火柴人、简笔线条或色点代替人像；
   - 对参战宗门（如青霞谷、阴灵门），用 `randomLook` + 对应宗门 `SECT_ROBE` 构造 **2–3 套制式男女弟子 `Look`**，调用现有 **`src/gfx/character.ts` 的 `drawCharacter(ctx, look, state, scale, dt)`** 预先烘焙 4–6 帧标准动作（待机、迈步、举剑齐射、受创溃逃）到离屏 Canvas / WebGL 纹理页中；
   - 阵中 100–200 名外门炼气弟子**共用这几张货真价实的游戏原版人物纹理帧**，根据 `slot.phase` 错开动画帧与微幅呼吸偏移，在 WebGL（`src/gl/batch.ts`）或 `ctx.drawImage` 中批量绘制——**既有 100% 原版道袍五官发冠细节，又只需极少 DrawCall 与像素绘制开销**。
2. **战阵特效与阵眼标识（源自 `formationEffects.ts` & `combatfx.ts`）**：
   - 阵眼位置与阵缘直接贴用 `src/gfx/formationEffects.ts` 的 `zf_flag_*`（按宗门五行/魔道属性选旗）、`zf_disc_ground`、`zf_link`（阵纹连线）与 `zf_dome`（护阵光幕）；
   - 阵眼队长头顶叠加 `zf_eye` 缩小图标 + 护盾条，敌我阵圈使用高区分度颜色（友方青/金，敌方赤/紫），混战中一眼分明；
   - 齐射剑雨、法宝流光与破阵爆炸全走 `src/world/combatfx.ts` 与 `src/gl/fx.ts`。

### 6.4 战损分流与战力防崩坏
- **实时触发保留**：继续沿用 `src/world/sectwar.ts` 的 `frontPos(w)` 近战区触发（`< 1700` 触发 `startBattle()`）与 `postTick()` 据点驻防逻辑（可升级为 1 筑基 + 小股外门列阵巡逻）；`reinforce()` 从“死 1 补 1 散兵”改为“某阵崩溃后从后备队列整编开上一座新战阵”；两翼未上场预备队继续走 `wings()` 结算。
- **伤亡三分账（避免打一仗变空城，又保持战损痛感）**：
  - **AOE 直接清剿**：`50%` 永久战死，`50%` 重伤进入 `outer.injured`（在山门按 30–90 天缓慢康复回流）；
  - **斩首阵眼炸阵溃散**：`25%–35%` 折损于反噬与追杀，`65%–75%` 溃逃归队回到 `outer.alive`；
  - **灭宗发落适配**：破门后选择「收编残部」可直接把敌宗剩余外门 `outer.alive` 与部分筑基种子并入己方；选择「灭其道统」则高层伏诛、残存底层部分流散为当地城镇散修/凡人虚拟池。
- **高阶战力压制修正**：修改 `sectwar.ts` 的 `pwOf` 线性堆叠算法——炼气池不按 `1 × 10000` 直接相加，而是折算成「可编成战阵数 × 阵法有效系数」，并在面对结丹/元婴时引入大境界压制折减（无同阶牵制时，低阶战阵对元婴伤害与推线贡献大幅衰减），防止出现“一万炼气堆死元婴老祖”的数值崩坏。
