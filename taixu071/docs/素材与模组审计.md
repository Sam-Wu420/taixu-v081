# 素材与模组审计（2026-11）

> 对应 `docs/人界改造_当前进度与后续计划.md` 的「后续任务 3」。本文只写**可复核的证据**：每条结论都能用文里的命令或测试重现，不凭目录名推测。

## 一、判定方法（为什么不信 grep）

只看目录名或关键词会误判：`mood.ts` 里到处是 `'mist_band'` 这类**字符串键**，但它们早已改由 `gfx/moodProcedural.ts` 现场生成，跟 `src/assets/mood/*.webp` 没有关系。所以这次分三步：

1. **构建产物**：`npx vite build --config vite.lowmem.config.ts`，看哪些文件真的进了包。
2. **模块图**：`?inline` 图片会被 Vite 直接内联成 data URL，不进 `dist/assets`；因此对每个可疑目录，再查「有没有任何模块 import 它」——结果是 5 个 `*Data.ts` 模块，而这 5 个模块**自己没有调用方**。
3. **运行时拼路径**：`grep -rn "\.webp\|art/"` 找动态拼出来的路径。只剩 `public/art` 一处（`data/portraits.ts` 的 `./art/npc|gen/*.webp`）。

再与「程序化替代」的回归测试对齐：`test-procedural-beasts` / `-atlas` / `-legacy-buildings` / `-legacy-paths` / `-interface`。其中三个测试的断言本身就是**「这些旧数据模块不得被 import」**，正好反过来证明它们已经下线。

**合计 522 个文件、约 22.3 MB。**

## 三、本次删除

- 11 个 `src/assets/*` 目录（341 个文件）＋ `public/art`（176 个文件）＋ 5 个孤儿模块（`gfx/beastTexData.ts`、`gfx/headTexData.ts`、`gfx/bldTexData.ts`、`gfx/v054Data.ts`、`gl/fxAtlasData.ts`）。
- 代码化简：`data/portraits.ts` 由 243 行缩到 14 行（只留 `portraitFor`）；`world/npc.ts` 的 `look()` 不再过 `tagLook`，直接返回 `lookRaw()`（`tagLook` 原本只做「登记」，返回值就是原对象，行为不变）。
- 效果：`src/assets` 15 MB → 1.1 MB；`public/` 9.3 MB → 21 KB；`npm run build` 产出的 `dist/` 42 MB → 33 MB。
- **图都在 git 历史里**，需要时可 `git show <旧提交>:public/art/npc/xxx.webp` 取回，或按 `tools/*convert.ts` 从外部原图重新生成（这些工具读的是仓库外的 art-incoming 目录，不依赖已删文件）。

## 五、模组通道现状（顺带核对）

- **数据覆盖**：`api.content.patch.*` 改原版字段、`api.data.*` 增删 43 张表、`api.registerIcon` 注册图标。
- **图片覆盖**：模组图标优先于程序生成的物品/技能图标——`test:item-icons` 断言了「模组显式注册的图标优先，其余走十类程序原型」。
- **坏数据兜底**：掉落钩子经 `safeHookDrops` 过滤（上限 1024 项 / 256 条、非法 id 丢弃、数量夹 1–9999）；数值钩子经 `hookNumber`。
- **尚未逐项验证**（留给后续）：图片加载失败时是否在所有绘制路径都回退到程序绘制；图标覆盖在背包 / 商店 / 法术书 / 获得法器四处是否表现一致。

## 六、复现本次审计

```bash
npx vite build --config vite.lowmem.config.ts      # 看产物
grep -rn "import .*from '.*assets/" src --include=*.ts   # 谁还在 import 资源
grep -rn "\.webp\|art/" src --include=*.ts --include=*.tsx  # 有没有拼路径
npx tsx tools/test-procedural-beasts.ts            # 断言旧模块不得被 import
npx tsx tools/test-procedural-atlas.ts
npx tsx tools/test-procedural-legacy-buildings.ts
npx tsx tools/test-procedural-interface.tsx
```
