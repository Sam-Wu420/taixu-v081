## 目标与约束

- 先完整实现人界。天南、乱星海、大晋是同一小千世界的三个地域；灵界、仙界先提出设计并确认后再开发。飞升后允许高成本返回人界。
- 以网页 WebGL 2 为主，保留人物程序绘制核心，其余代码可重设计；最终视觉使用程序绘制，不使用外部美术。允许程序生成的纹理缓存及音乐、音效、字体文件；物品尽量数据驱动。当前使用原版名称，对外发布前须完成权利核查与必要替换。
- 场景可简化，优先性能；目标是在代表性集显设备稳定 60 FPS，独显可不主动限帧，提供画质预设与自定义。**任何自动测试或沙箱结果都不能代替真实设备验证**。
- 持续开发并在验证节点提交、推送；不分阶段要求用户测试，全部工作完成后统一验收。旧存档不要求完全兼容，但现有读档保护不能无故退化。

## 已完成的主要工作

### 一、人界、存档与战斗基础

- 已建立人界三地域、0–23 级数值和存档 v3 的基础，加入关键数值与读档预检、压缩存档、跨地域远行检查点及失败恢复。以上不等于人界玩法、数值和平衡已全部完成。
- 存档现状：`SAVE_VERSION = 3`；四个槽位（`fanren_save_auto` + 1/2/3）；`savezip.ts` 自写同步 LZSS（`z1:` 前缀，实测 420KB → 105KB），明文老档原样可读；解压长度上限 64MiB（`MAX_SAVE_BYTES`）。
- 读档保护：`saveGuard.ts` 预检地图、坐标、世界比例与部分嵌套结构（含 `savedDrops`）；`latestSlot()` 逐槽校验，坏档被跳过；存档失败区分 `quota` / `denied` / `serialize` 三类并给出对应文案。**这不是完整 schema 校验，也不是事务回滚。**
- 战斗数值：境界倍率计算做了上下界约束；持续性伤害只结算状态实际剩余时间（长帧不再多扣）；主要直接命中入口会拒绝异常数字。

### 二、奖励与掉落（原「后续任务 1」的主体已完成）

- **固定奖励计划 + 背包 / 状态原子结算**：古战场、古修遗骸、野外遗骸、名地一次性遗物与守卫、灵池潜水、兽巢、药王、赌斗、夺舍残魂、护送与护法、劫修、秘境宝箱、藏宝图与神龛，均已改为「先算好整批奖励，再一次性入袋；入不进去就留在脚边」。
- **受保护补发掉落**（`savedDrops.ts` + `combatDropSafety.ts`）：背包拒收时掉落标 `blocked` 留在原地可重试；存档时只把「已标记、未收取、未在收取中」的掉落按**地域**写入 `savedDrops`，读档时当前地域直接恢复、其他地域按世界比例换算后保留。秘境内存档记在入口（`realm.back`），与大地图掉落**相互隔离**。
- **回调重入**：单帧快照 + `updatingDropLists` 弱集合，回调里新建的掉落不会被本帧清理掉；拾取通知的重入与重复入袋已加锁。
- **模组边界**：掉落钩子的结果经 `safeHookDrops` 过滤（最多 1024 项 / 256 条、非法 id 丢弃、数量夹在 1–9999），模组塞坏数据不会打断战斗。
- **重置路径已补齐**（原先 `Combat.reset()` 无条件清空 `combat.loot`，五条调用点会白白吞掉补发掉落）。现在按「掉落该去哪」分成两类：
  - **留在原地**（`game.resetCombatKeepingDrops()`：摘下 → 重置 → 放回原坐标，同一个对象）——魔修掳入血煞洞窟（`renxin.ts` `handleDemonCapture`）、战败后被移到安全处（`renxin.ts` `evacuateToNearestTown`）、死敌补刀的无存档兜底（`renxin.ts` `handleMortalEnemyFinish`）。人被挪走，东西留在跌倒的地方，走回去还能捡。
  - **随遗物入碑**（`game.protectedLoot()` → `DaoxinSys.onTrueDeath(killer, cause, killerId, extraDrops)`，同名条目合并、非法条目丢弃、碑文补一句「脚边尚散着 N 件」）——天道档真死（`renxin.trueDeath`）、寿元耗尽坐化（`daoxin.onAgeDeath`）。下一世在碑前取回。
  - 远行（`travel.ts`）与读档（`game.ts`）本来就没问题：都是先 `save(0)` 成功再 reset，读档时 reset 后立刻用 `savedDrops` 恢复；死敌补刀的回档分支也由随后的 `load()` 覆盖。
  - 回归：`npx tsx tools/test-drop-reset.ts`（18 项：保留语义、秘境石台、碑遗物合并与非法输入、调用点传参）。
