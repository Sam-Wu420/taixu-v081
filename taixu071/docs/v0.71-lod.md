# v0.71 · 全局 LOD 算法

> 目标：所有绘制与更新系统用**同一套算法**决定「画多细、多久更新一次」，细节随缩放**连续**增减，
> 只有小到看不见（不足一像素）才真正跳过。不再各系统自己写 `z < 0.35` 这类硬阈值。

## 一、唯一标尺

| 量 | 含义 |
|---|---|
| `E = zoom × dpr` | 一个世界单位占多少设备像素 |
| `px(w) = w × E` | 世界尺寸 `w` 的物体在屏幕上的设备像素尺寸 |
| `k = smooth(a, b, E)` | 细节权重 0→1（`a` 起、`b` 满），判定依据是「屏上多大」，不是缩放值本身 |

角色的局部单位另有一套（`CHAR` 波段，单位是局部像素；170 单位的角色 ≈ `170E` 高）。
**全局自适应**：`noteFrame(ms)` 用帧时间 EMA 调 `bias`（0.75–1.15），所有系统把 `E` 乘上它，
掉帧时一起少画、回稳后慢慢补回——不用各写「低配模式」。

## 二、五个算法原语（`src/gfx/lod.ts`）

| 原语 | 作用 | 算法 |
|---|---|---|
| `fade(ctx, k, fn)` | 细节淡出 | `alpha ×= k^0.7`；`k≈1` 零开销；`k≤0.02` 直接不调用 |
| `keep(level, k, hash, maxLevel)` | 密度抽样 | `p = clamp(k·(maxLevel+1) − level, 0, 1)`；同一坐标哈希恒定，整片变疏而非成片消失；第 0 档永留 |
| `geom(base, k, min)` | 几何简化 | 顶点数 `round(base·(min/base + (1−min/base)·k))`，单调、不低于 `min`（形状不碎） |
| `res(wantPx)` | 贴图降档 | 只要 0.5 / 1 / 1.5 / 2 档，按需求像素取够用的一档（`resBucket` 是它的缓存量化版） |
| `cadence(k, maxStep)` + `phase(i,n)` | 更新节流 | 权重越低，AI / 物理 / 动画更新间隔越长（1–4 帧），配合错相位避免同帧齐动 |

## 三、各系统接入情况

| 系统 | 用的原语 | 现在的行为 |
|---|---|---|
| 水面 / 倒影 / 云影 | `fade` + `BAND.water/reflect/cloud` | 低于约 0.33px/单位淡出，看不见才跳过 |
| 丛草 | `fade` + `keep(grassTier)` | 三档密度按哈希连续抽稀（不再 `z<0.65` 一刀砍掉两档） |
| 地面装饰 | `fade` + `BAND.deco` | 拉远时淡出，不再 `z<0.3` 硬切 |
| 树木 | `keep`/`fade` + `treeNear/treeFar` | 三档按屏上大小淡入淡出（原有硬剔除已换成连续） |
| 角色 | `CHAR.hand/cloth/fine` | 手部 IK 权重、布料/发丝摆动步长、≤1px 细节开关都连续；物理 `dt` 乘权重并夹 0.05，掉帧不过冲 |
| 建筑匾额 | `fade` + `BAND.bld` | 从 `Z>0.45` 硬切改为淡出，字看不清才不画 |
| 地名 / 名牌 | `fade` + `BAND.label` | 小地名随权重淡出，主城名恒在 |
| 山 / 瀑布 / 建筑贴图 | `resBucket`（= `res` 的量化版） | 只烘到够用的分辨率，已有 |

## 四、物理不能用细节权重当时间步（踩过的坑）

第一版为了「远处省电」把布料/发丝的积分 `dt` 乘上 `clothK`。小角色的 `clothK` 恰好是 0 →
`dt = 0` → 丝带不再积分，点停在**旧的世界坐标**上；角色一走开，画出来就是一条横贯屏幕的长线
（头带、袖子像被钉在原地）。两处修正：

1. 物理一律用真实 `dt`（夹 0.05）。远处要省，就整块 `fade` 到 0 不画，**不是让积分停住**；
   `clothK` 只用来缩「摆动幅度」这个视觉量。
2. `Strand.step` 的 `dt <= 0` 分支原本是死代码：先把 `x[0]` 改成锚点、再算 `ddx` 永远为 0，
   整条丝带留在旧位置。改为先算位移再整体平移。

同理，手部 IK 也不能按 `handK` 缩 `dt`（过渡区会变「慢动作」），只在 `far` 时整块停。

关于「和世界坐标有关吗、不该依赖速度吗」：丝带的每个节点确实存**世界坐标**（这样它才会自然拖在身后），
但驱动它的是——锚点位移、角色自身速度（`st.vx/vy`，已夹在 ±420）、风与重力；位置本身只是积分结果的容器。

回归测试：`npx tsx tools/test-character-lod.ts`（6 项，见下）。

## 五、硬阈值迁移（v0.72 已完成）

原先各系统各写一套 `z > 0.3 / 0.35 / 0.4 / 0.45 / 0.5 / 0.6`，缩小到阈值就整块开关，
观感上能明显看出「做了一次操作」。现全部改为统一波段（`src/gfx/lod.ts` 的 `BAND`）：

| 原阈值 | 系统 | 现波段 |
| --- | --- | --- |
| `z>0.4` | 落花飞雪密度 | `sparkle` |
| `z>0.45` | 水面粼光 | `sparkle` |
| `z>0.4` | 岸边浪花 | `shore` |
| `z>0.35` | 河流水光 | `river` |
| `z>0.3` | 瀑布水练 | `fall` |
| `z>0.45` | 瀑布动画 | `fallAnim` |
| `z>0.45` | 树影倒影 | `reflect`（原有） |
| `z<0.3` | 城中树隔行剔除 | `treeNear` + `keep` 连续抽稀 |
| `z>0.3~0.35` | 熔岩余烬 / 血潭涟漪 / 祭坛血光 / 遗骸光环 / 熔岩飞灰 | `groundFx` |
| `z>0.35~0.5` | 倒影雨圈 / 锦鲤 / 流萤 | `scape` |
| `z>0.22` | 地名 | `label`（按权重乘 alpha） |

迁移后的写法统一为「取权重 → 乘 alpha 或按概率抽稀」：
`if (kk > L.GONE)` 只作为「完全不画」的省算判据，**画面上的浓淡由 `kk` 连续给出**。
仍保留的少数 `z < 0.6` 是「缩小时额外多显示东西」（远景名牌、大字标签），
其本身带 `clamp((0.6-z)/0.3,0,1)` 的连续 alpha，不属于硬切。

### 5.1 树：精灵 ↔ 林色块（v0.72）

树的降级终点不是消失，而是**同色的地图小块**：远看是一片林子，放大逐渐看出树冠，再放大成为真树。

- `TREE_TIER = [1.5, 6]`（屏上树高像素）；`treeTiers(px) → { sprite, cover }`，两者**严格互补**（和为 1）。
- 林色来自 `gfx/tree.ts` 的 `coverColor(sp, season)`，与真树同一套 `foliageColors` 配色，
  所以树种/季节不变时色相恒定 —— 缩放过程中不会「换一种绿」。
- 位置不另算网格：林色块直接画在**代表树的真实坐标**上（`world/landCover.ts`），
  因此换挡时是「同一棵树由虚变实」，不存在色块与树错位的抖动。
- 三处接入：宏观摘要（`farSummary`）、极远批绘（`drawFarTreeSprites` 前铺色）、
  常规路径的小树带（`< TREE_TIER[1]` 走交叉淡入，6px 以上回正常画真树）。
- 山脉宏观脊线保持约 1.6 CSS px，不增粗成色带；单座山的外轮廓始终保留，远景只压低内部松点 / 苔点 / 裂纹等碎细节，近景逐渐恢复，8px 山影再连续长到真实尺寸。
### 5.2 极远：整片林色底（v0.73，`world/canopy.ts`）

树上只有「真精灵 / 林色块」两种表示，极远视野仍然会两头不讨好：逐棵画既慢又看不出是林子。
所以再加一层**整片林子的底**：

- 按缩放与视野面积选纹素尺度：受 `MAX_TEXELS` 总像素预算约束，屏幕采样上限由当前 padded view 面积动态推导；缓存仍覆盖视口且采样不超出预算加 1 CSS px 余量时只重采样，不因 zoom 浮点变化重烘。超出可见范围或线性质量阈值才后台重烘。
  把视野附近烘成一张位图：逐纹素采样地形的 `forest` 场，叠上花林（桃/枫/杏）的树种色，
  颜色一律走 `coverColor`，与真树同一套配色。
- 浓淡不按缩放硬切，而按**缺口**：`canopyAlpha(cap)` = 「这一块本该有多少树、这一帧实际能画多少」的差额。
  极远只画 24 棵代表树 → 缺口接近满值（整片是林色）；放大后上限升到 120 棵 → 缺口归零，色块自己退场。
  两条渲染路径（宏观摘要 / 近景）用同一个函数，切换处两侧数值只差 0.06，看不出换挡。
- 每帧只有**一次 `drawImage`**（此前极远是逐棵铺色块，几千次 fill），这正是远景卡顿的一大来源。
- 半成品不贴；重烘期间保留上一张完整林色贴图，首张图完成前才不画，避免缩放或镜头移动时整片林色闪没。
- F3 面板可直接看「宏观摘要 / 近景 · 林色 就绪 x% w×h 重烘 n 次」。

- 树上还有一层 `plan()` 的预算与 `representativeTrees` 抽样：抽样只改「每块画多少棵」，
  不再承担「降到多小」的职责，因此不会在远处出现整片抽空。

## 六、验证## 六、验证

- `npm run test:lod`（`tools/test-lod.ts`）：**39 项**
  - smoothstep 单调、两端夹紧；波段外取 0/1、波段内取中间值
  - `keep`：满权重 100%、零权重 0%、中间密度（第 1 档 50%）、档位越高越早抽掉、第 0 档永留
  - `geom`：4→16 单调、任何权重不低于下限
  - `res`：0.5→2 单调、`max` 生效
  - `cadence`：满权重每帧、零权重每 4 帧、单调不增
  - 自适应偏置：模拟 30fps 掉到 0.75、模拟 125fps 回到上限、夹紧在 0.75–1.15、后台巨帧不计
  - 波段表自洽：全部 `[起, 满]` 且 起<满
  - 树的两段表示：`sprite + cover ≡ 1`（偏差 0）、越远林色权重单调不减、`<1.5px` 只剩色块、`>6px` 全是真树、
    换挡带内两者并存；`coverColor` 同树种同季恒定、不同树种可区分、随季节变化；
    林色底跨远景摘要交接权重两端对齐且单调；山体外轮廓保持
- `npx tsx tools/bench-lod.ts`（20 人一帧，单人 ms，Node canvas 近似值）：
  `16px 0.49 / 24px 0.41 / 40px 0.41 / 64px 0.43 / 96px 0.42 / 160px 0.55 / 300px 0.74`
  —— 迁移前同环境是 `0.58 / 0.47 / 0.48 / 0.50 / 0.47 / 0.64 / 0.90`，小尺寸与特大尺寸都略有下降。
- `npx tsx tools/test-character-lod.ts`（6 项）：远看时丝带最远点 8.7 段长（正常范围，被钉住会是几十上百段），
  `dt=0` 瞬移 400 单位后仍贴合，速度 2 万仍受控，大小两种缩放的积分结果一致。
- 面板冒烟 `tools/test-sectpanel.tsx` 147 项、`tsc`、slim 构建均通过。

### 5.3 山脉交接与神识信息稳定（本轮）

- 按用户二次反馈撤销「山体整体淡入淡出」：山脉脊线与单座山外轮廓不以 alpha 整体剔除；只调整山体纹理与内部点缀密度。林色底在宏观摘要退出前对齐常规权重，避免跨阈值亮度跳变。
- 右侧「神识信息」在疾飞时采用更低的刷新频率（普通飞行 650ms、催动遁光 850ms），失去感知的条目最多保留约 1.05 秒并标注「余韵」、淡出且不可点击；关注条距离文本节流到约 2.9Hz。方向箭头、世界标记仍逐帧跟随，不牺牲操作反馈。
- F3 实测确认是 WebGL 路径；另修正宏观分支的 profiler 游标未归零问题，之前「R·倒影」时间重复包含了极远林批绘，之后读数才可比较真实分项。
- 本轮自动化验证能覆盖权重单调与阈值端点；真机缩放观感、极远帧率及「余韵」时长仍需实机确认。
