## 二、做事的规矩（用户的偏好，记忆里也有）

- **回复**：一律用简体中文。代码注释、界面文字也用中文，写清「为什么」。
- **给用户试东西**：给实测过的网址或游戏里的入口，不给控制台代码片段。
- **无缝**：意思是玩家自己操作着飞过去。不放过场、不闪白、不黑屏遮挡，也不因为正在打斗就不让走。
- **衔接要自然**：地图上看着自然还不够，真实游玩时飞到图边、交界、图角，地面也要连着、岸线要曲折。用户原话：「不能光是地图自然，真实游玩的时候的地图衔接也要自然呀」。改了地图的显示，就要到游戏里那个位置实拍一张。
- **画风**：
  - 水墨加鎏金漆器。
  - 云雾、光晕只能点缀，不能糊住建筑和人。
  - 秘境、副本用开阔的石台，不做墙和窄道。
- **界面动效**：只动 transform / opacity。在 WebGL 上动 filter、blur、box-shadow 会卡帧。
- **按键**：新加的核心按键不能默认占数字 7–0，那是留给模组的。
- **包体**：交付的源码包不超过 120 MB，自己的目标是 90 MB 以内。画面内容尽量用代码现场生成；必须用的贴图压成 webp，单独记账。
- **画风相关的改动**：先出样板或概念图给用户看，点头了再铺开。
- **先说想法**：用户说「先告诉我你的想法，先不要动手」时，只讲方案，等他回话。
- **提交**：每完成一块就在 B 版提交一次，提交信息用中文。用户允许过用两个 Opus 5.5 high 子代理并行干活，做法是：
  - 每人一个 git 工作副本，放在 `重构v0.57\验证\` 下，各开一个分支；
  - 写清每人负责哪些文件，互不重叠；
  - 主线负责合并，合并后重新跑全量测试、重新截图；
  - 子代理交上来的结论要在主线上复核。它们的截图、「测试全过」这类说法以前错过不止一次。
- **固定种子的测试**：有几项测试固定了随机种子和假时钟（`tools/fixed-clock.ts`）。生成代码多取或少取一个随机数，结果就会翻。遇到失败，先用改动前的提交开一个临时工作副本对照（node_modules 用目录联接接过去），再下结论。

### 4. 图外衔接（`a454fa6`）

起因：用户先说世界地图上「衔接不自然」，接着说「真实游玩的时候的地图衔接也要自然」。原来的问题是：不通的图边外什么都没有，地面一出图边就断；天穹草原是一整条直边的横带。

- **`world/terrain.ts`**：
  - 不通的边外铺一圈六万宽的海（`SeamFrame.ocean`，`oceanValue`）。图边那一行的地貌揉着化成深海，`hasChunk` 也按这圈海放宽了范围。
  - 天穹草原改成一条地峡：从南荒北缘的宽度渐渐收到中州南缘的宽度（`SeamFrame.span`，`outShut`）。
  - 地峡两岸按大陆坐标的噪声揉出湾和岬（`toOcean`），所以南荒、中州两边算出来是同一道岸。中段起伏大，靠近两张图时收拢。
  - 大幅的起伏只给西侧，东侧有草原自己的东海岸。
  - 贴着两张图图边那一成深度不化海，保证图边内外连续；越出梯形的图角外照常化海。
- **`world/outland.ts`**：草原东岸加了中尺度的湾岬。原先在地峡那一段，东岸几乎是一条竖线。
- **世界地图**：`HomeMap` 图外那一层直接问每张图的 `Terrain.groundColor`。只问各图管得着的范围，范围边上渐隐。所以世界地图上看到的，和游戏里飞到那儿看到的是同一份。
- **踩过的坑**：
  1. `toOcean` 开头原来有一句「离岸远就原样返回」，把后加的内收和起伏全跳过了，改了好几轮都没效果。改这类函数时，先在页面里用 `__game.terrain.groundColor` 逐点探一行，确认真的变了。
  2. 岸线往里收太多会把草原上的营地淹掉。`genFrontier` 的营地一直摆到中州西缘往里一万二，是 `test-sea-cross` 抓出来的。
  3. 图边外那一格的值会沿着交界拉出一道细线，所以越出地峡的地方要按越出的距离 `d` 化海，不能看离图边多远。
  4. 南、东两条边的深度要从 `H`、`W` 量起，不能从 `H-1`、`W-1` 量起，否则两张图算出来的地峡不是同一个梯形。
- **测试**：`test-seam`（两边逐项一致、图边内外连续）、`test-sea-cross`、`test-seam-cross` 都过。
