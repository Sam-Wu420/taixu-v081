# 太虚问道录 v0.57 B 版源码交接

本包包含 B 版 HD2D 源码、独立预览、天工试场源码和可导入模组。实机、GPU、性能与预览沙盒操作记录见文末。

## 来源与实现范围

本轮修改前的 B-HD2D 基线为 Git 提交 `15ca21d`，A 版优化基线为 `e0a6148`。本次交付为 B 版，保留原仓库的 Three.js 依赖，版本为 `0.187.0`；本轮未增加生产依赖。

优化思路参考工作区中的 `太虚问道录重构-源码工程-20261108/work/taixu-rebuild`。战斗空间查询和地形分块借鉴该工程的方案，结合 B 版现有数据与玩法重新实现；NPC 每日结算也经过 B 版适配，具体实现以本包源码为准。

- `src/hd2d/scene.ts` 管理倾斜正交相机、立板和地形绘制，Three 场景直接绘入原有 GL 合成使用的共享 GPU 目标。地贴复用地形三角面并保留深度测试；神识和云雾读取独立的地表深度，角色、建筑和特效继续使用最近物体深度。每次重绘场景会进行一次 GPU 深度复制；新增深度纹理在 1080p 下按每像素 4 字节估算约 7.9 MiB，实际显存由驱动决定。
- `src/hd2d/buildings.ts` 根据原地点布局和调色板生成带屋顶、侧面及厚度的程序网格。旧式房屋、墙、塔与新版建筑、墙段按地点使用共享材质和实例批次，门洞结合原有碰撞布局确定；其他小件继续使用原画法。
- `src/world/surface.ts` 按宏观高程、门派平台和道路计算地面高度及坡度。行走、飞行落地和相关单位移动使用地面规则，原游戏世界坐标仍用于玩法。
- `src/world/terrain-chunk-*` 将地形块烘焙放入 Worker，并按视野与移动方向安排请求。后台不可用时保留同步路径；切换季节或退出渲染器时处理旧任务和资源。
- `src/world/spatial.ts` 为战斗中的邻近查询提供空间分组，战斗网格使用 64 单位格，候选结果仍由战斗逻辑作精确判定。`src/world/npc-day.ts` 将 NPC 每日结算分帧，存档前补算待处理日程。
- `src/gl/` 中的战斗贴图、弹道与粒子支持按世界位置和高度投影及深度遮挡。贴地特效沿 64 单位地形网格切分，保持贴合坡面；`src/gl/stage.ts` 使用高精度深度采样和反投影定位神识及氛围，并按主角深度应用轻度景深。角色施法动作与衣物摆动的状态更新也有调整。
- HD2D 的雨雪和空气覆盖层使用半分辨率画布，世界、人物和 UI 继续使用各自的原有分辨率预算。
- `src/hd2d/staticAtlas.ts` 复用草丛、静态小景、城中小件与人物缓存的图像，图集大小为 4096 × 4096，RGBA 纹理约 64 MiB。已分配的槽位按图像版本局部上传，连续 120 帧未使用的槽位可回收。上下文恢复时从当前图像重建整图。草丛仍随风和人物移动，树木与旗帜继续动态绘制。动态工作纹理仍逐帧上传，两个图集分别计算预算。
- 人物后台绘制不可用时，密集场景中的远处小人物使用 `src/gfx/character-cache.ts` 保存单人画面。视野范围内收集到至少 120 个战斗单位时，距主角超过 220 世界单位且投影缩放不超过 0.85 的单位进入缓存，主角、锁定对象和近处人物保持实时。首次出现时同步绘制以建立缓存。之后单人画面最多每 100 毫秒刷新一次，每帧轮转约四分之一的候选角色、最多 256 人，低帧率下刷新会更慢。动作状态和手势逐帧推进，人物位置、冻结等状态叠层与特效仍逐帧呈现，布料时间在重绘时补算。
- HD2D 收集到至少 80 个战斗单位时，普通不透明小人物优先进入 `src/gfx/character-worker-frames.ts` 的双 Worker 路径。首次画面同步生成，后续批次按空闲 Worker 分摊，每批最多 128 人，继续调用 B 版原 `drawCharacter`。CPU OffscreenCanvas 绘制后转移 ImageBitmap 和衣发数组，主线程更新位置、手势和状态层。主角、锁定对象、神识边缘半透明人物、头部贴图及放大人物使用原绘制。后台绘制不可用时使用上述缓存。GPU 与 CPU 光栅的边缘抗锯齿有差异，人物造型和施法内容保留。
- `mods/shahe/` 包含试场的点选、收起、快捷键、临时新局和演武台地形适配。演武台云海交给 GPU 平移采样，台面按分辨率与素材版本缓存。原先被不透明云海覆盖的水面与地点地贴会清除，避免改变遮挡顺序。演武台中暂停自动奇遇等干扰，出阵时恢复对应状态。摆设阴影贴地，摆设图像面向镜头。

## 本地工程参考

重构版的 `src/render/characters/geometry-client.ts` 使用双 Worker 和延后结果复用。其几何构建器与 B 版原画布人物的细节存在差异，实际对照发现缺少施法手部光效，因此 B 版沿用原 `drawCharacter`，借鉴后台调度方式。

按用户指定目录检查的 Idle Colony 使用共享居民动画格，行走与搬运均为 4 帧、每秒 7 帧。居民和字体 shader 支持纹理编号与 16 个纹理槽，字体另有字形图集。这些资源支持动画共享与文字合批的优化方向。其原生 AI、空间索引及线程调度函数体尚未取得，不能据此认定具体算法。B 版的人物有独立外观和衣发状态，当前保持每名角色独立绘制。未将 Idle Colony 的素材或程序复制进本交付包。

## 素材来源

地形与建筑没有新增生成纹理。地表继续使用 v0.57 原有素材和程序绘制，房屋与城墙根据原布局尺寸、碰撞和色板生成几何。人物、特效、图片与音频沿用原项目资源。

沙盒面板和图标来自现有的 `shahe-1.3.0.fmod`，本工作区的原包位于 `重构v0.57/测试模组/shahe-1.3.0.fmod`，相应资源已同步到 `mods/shahe/img/`。本轮没有调用图片生成工具，也没有引入外部新素材。

原美术说明保留在 `docs/art-brief/`。音效和乐器采样的来源记录见 `tools/sfxbuild.py`；库版本及许可证以锁文件和依赖自身文件为准。

## 预览与开发

解压交付包后，安装 Node.js 并运行下面的命令。

```powershell
node .\tools\preview-b.mjs
```

在浏览器打开 `http://127.0.0.1:5302/`，按 Ctrl+C 停止。预览服务只使用 Node.js 内置模块，无需先安装 npm 依赖。HD2D 画面需要浏览器支持 WebGL2。

`preview/asset-map.json` 将预览资源映射到 `src/assets/` 和 `public/`，源码与预览共用图片、音频；编译后的脚本、样式和字体位于 `preview/`。修改源码后需要重新打包才能更新交付包中的预览。

开发与构建使用仓库锁文件。

```powershell
npm ci
npm run dev
npm run build
```

开发地址为 `http://127.0.0.1:5202/`，构建结果位于 `dist/`。画面及世界路线验收页位于 `tools/hd2d-check.html` 和 `tools/world-acceptance.html`。世界路线页的自动存读档限定在独立的 `127.0.0.1:5214`，可用下面的命令启动不监视文件的测试服务。

```powershell
npx vite --host 127.0.0.1 --port 5214 --strictPort --config tools/perf-vite.config.ts
```

启动后打开 `http://127.0.0.1:5214/tools/world-acceptance.html`，选择场景后进行操作。

## 首次导入天工试场

1. 在标题界面打开“模组”，选择本地导入并选取 `dist-mods/shahe-1.3.0.fmod`。
2. 启用模组，按游戏提示确认高级权限并重新载入。
3. 从标题界面进入“天工试场”，或在游戏内按反引号键打开试场；F2 快捷键可用时也可使用 F2。

已有存档时，入阵前会保存自动存档，出阵后读回；临时新局出阵后回到标题。试场内拦截游戏存档。

修改沙盒源码后重新生成模组包，再重新导入浏览器中的模组。

```powershell
npx tsx tools/mod-pack.ts mods/shahe
```

## 重新打包

在源码目录先执行 `npm ci`，然后运行 `node tools/package-b-source.mjs`。脚本复制当前源码快照、构建共享素材预览、按同一快照生成沙盒包并制作 ZIP。默认输出到源码目录上一级的 `验证/`，也可将目标 ZIP 路径作为第一个参数。Windows 使用系统 `tar.exe`，其他系统需要 `bsdtar`。

打包脚本限制 ZIP 不超过 70,188,812 字节；原版完整源码 ZIP 为 58,490,677 字节。包内排除 `node_modules`、`tools/out`、历史构建和其他额外模组。为控制体积，旧任务书的 `docs/art-brief/ref_v054/` 参考截图未收录，文字说明与运行素材保留。

## 已知限制

HD2D 场景需要 WebGL2，浏览器无法创建 WebGL2 时游戏回退到 Canvas2D。地形后台烘焙依赖 Worker 和 OffscreenCanvas，相关能力不可用时回退同步生成。

立板共用固定容量的工作图集，空间不足时先降低分辨率重新排布；实例总数超出 4096 或无法排布时，部分立板仍可能在当帧跳过。静态图集满时草丛退回动态图集，动态草的占用上限仍可能使其被跳过。

本轮最终测量使用 1920 × 1080、自动画质，百人与千人各预热 5 秒、采样 15 秒。百人为 36.00 FPS，千人为 9.32 FPS。千人仍明显卡顿，普通探索 60 FPS 目标也需要单独验收。千人人物 Worker 的平均画面年龄约 316 ms，位置每帧更新，身体动作刷新存在延迟。神识边缘半透明人物直接绘制约 19.87 ms/帧，伤害文字约 14.33 ms/帧，仍是主要开销。

早期 40 敌连续施法三轮采样为 36.67、66.73、55.28 FPS，早期千人三轮为 3.97、3.76、3.80 FPS。这些数据对应历史版本。跨日场景曾出现约 1.05 秒与 1.95 秒长帧，原因尚未完全定位。

## 验收记录

- 本轮修改前的 B-HD2D（`15ca21d`）与千人优化前的 B 版分别在梁京来回、40 敌连续施法、长途飞行、跨日自动存档四个场景各测 3 轮，每轮 60 秒，预热 5 秒。两版各 12 组均完成采样，未报告背景暂停和帧错误。后者采样在 FX 拖尾投影、跨日紧接跨图结算的修复及雨雪/空气层分辨率调整之后。
- 采样中的 CPU 数据为 JavaScript 主线程计时，内存数据为浏览器暴露的 JS 堆，GPU 计时取决于浏览器支持；它们不能直接代表系统 CPU 占用率、进程总内存或显存。
- 实机已走通青玄门上下山及青霞谷上下山。青霞谷从地面高度 14.9 升至 420，中途高度 200.7 时存档重载位置差为 0；山顶完成飞行、降落及存档重载。
- 镜州街道已走通，并在 45°、135°、225°、315° 查看建筑；叶家城墙门洞已正反通过，中点存档重载位置差为 0。
- 修复后重新运行 GPU 投影与深度测试，45 个用例通过，最大投影误差约 0.000668 像素，GL 错误为 0；火弹图片和几何体的前后遮挡、高精度神识显色通过。
- 地表深度拆分后的 GPU 对照将立板透明度从 0.039 调至 0.041，原最近深度模式的神识颜色跳变为 44，新地表深度模式为 2，关闭神识为 6；尺寸变化的深度纹理与帧缓冲释放检查通过。青霞谷近似位置开启神识和迷雾往返移动、转镜约 180°，未观察到此前的整片颜色跳变，控制台错误为 0；复验路线与视频不完全相同。
- 青霞谷北坡贴地神识圈的旧网格有 62 / 156 个采样点落在地表后；64 单位网格修复后，0°、45°、90° 各 629 个采样点均在地表前。该问题与用户视频的闪烁主因分开记录，局部 CPU 代价见验收报告。
- 1080p 前台千人对战在优化前后各测 3 轮、每轮 60 秒，500 友军对 500 敌军；为稳定负载，测试设置高血量，正常沙盒预设使用正常血量。优化前三轮 2.45、2.48、2.61 FPS，优化后三轮 3.97、3.76、3.80 FPS，全部 1000 人存活且持续造成伤害。逐轮帧间隔、游戏时间和原始记录见验收报告。
- 5302 预览已验证首次导入和启停重载沙盒；荒野木桩阵、原地化身、暂停单步、倍速、夜雨、飞行、施法及出阵流程均已操作。演武台生成 40 敌，连续施法产生伤害和击杀，清场撤下剩余 36 个单位。
- 演武台 14 组摆设阴影与立板分层通过无头绘制回归，未逐件进行实机观察。

逐轮性能、独立端口首次访问、微基准结果和原始 JSON 收录在 `docs/b-hd2d-acceptance/`。工作区里的截图和现场日志保存在 `tools/out/b-hd2d/`，该目录不随源码包分发。
