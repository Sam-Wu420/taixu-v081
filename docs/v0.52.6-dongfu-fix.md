# v0.52.6 补丁说明 —— 洞府交互修复

基于 main 分支 v0.52.5（ee5a9a6）。只改源码，`npm run build` 通过（tsc 零错误）。

## 一、进洞府时有时无（P0）

**根因**：洞府建在灵脉上，`home` 与 `sites`（灵脉）的位置几乎重合。`interact()` 把候选按距离排序，
`[sites.focusD, sites.interact]` 与 `[home.focusD, home.interact]` 排在一起时，玩家站得偏一点就先命中「查看灵脉」，
而 `sites.interact()` 返回 true 直接结束——**洞府那一支永远轮不到**。所以同一个位置，有时能进、有时没反应。

**改法**（`game.ts` `interact()`）：算出洞府实际距离 `hd`，`hd < 320 && hd <= siteD + 40` 时，
把 `sites` 那一支压到 1e9、`home` 那一支提到最前——洞府附近无条件优先进府。

**顺带**：`enterCave()` 从「静默 return」改成每种失败都有回话（没洞府 / 不在此地 / 离太远 / 战斗中），
并在 `inCave` 残留时先 `leaveCave()` 自愈，避免「一次异常之后再也进不去」。

## 二、竖屏进去像黑屏（P0）

**根因**：`scale = Math.max(W / LW, H / LH)` 是 cover。竖屏 390×844 时 scale≈0.94，
1600 宽的图被拉到 1504 宽、居中后左右各裁掉 557——**主角初始 x=200 直接落在屏幕外**，
玩家看到的只是石室正中一小块较暗的区域，很像黑屏；石榻（x=1450）更是永远走不到。

**改法**（`CaveScene.tsx`）：
1. `scale = max(H / LH, W / LW)` 高度铺满，`viewW = W / scale`；
2. 相机 `camX` 跟随主角并夹在 `[0, LW - viewW]`——竖屏也能走到石室每一处，主角始终在视野里；
3. 点击坐标反算补上 `camX`（原来会把点击判到错误位置）。

## 三、洞府选项找不到（P0）

**根因**：v0.52.5 把 `home.interact()` 从「弹完整菜单」改成「进独立场景」，而原来那些选项
（**布置禁制 / 扩建药园 / 以地火重炼古宝 / 照看灵宠**）只剩石榻一个入口。石榻在 x=1450，
竖屏根本走不到——等于整个功能被藏没了。

**改法**：洞府顶部加常驻功能条，不必走动也能开：

```
药园 · 丹炉 · 蒲团 · 地图 · 洞府事务 · 出府
```

- **洞府事务** = 直接调 `home.mainNode()`，老菜单一项不少；
- **地图** = 直接开世界舆图（找传送阵、城池、宗门，不用记 M 键）；
- 其余四个直接进对应面板。

## 四、其他

- **提示点对齐**：热点圆点与文字从「人物站立点」移到「物件本身」（`s.y - 200`），点在药园上就标在药园上；手机点击判定同步。
- **贴边不裁字**：提示文字夹在视口内，相机在最左/最右时不会被屏幕边缘切掉。
- **整帧 try/catch**：`loop` 里任何一帧抛错都只降级画底色 + 一行提示，**不再断 rAF 链**（断了就是永久黑屏）。
- **`home.q()` / `placeMult()` 防御**：老存档缺 `q` 或算出 NaN 时兜到 1.4，不再显示「灵气 ×NaN」。
- **`h.plots` 判空**：`Array.isArray` 后再遍历，防老存档缺字段让整个洞府帧崩掉。
